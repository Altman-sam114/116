# WW2Tactics — 二战六角战棋

原生 SwiftUI iOS 回合制战棋原型。v3.2 延续战争沙盘全面重构：原创具象军械、疏密林地、连续水岸和桥梁、六角战术叠层与短横屏指挥界面。本轮按要求百度搜索《将军的荣耀3》遇验证码，公开相册 403；没有绕过，随后通过 Apple 官方商店 API 实看该游戏冬季、夏季与横屏公开截图，仅对照风格，不保存或打包商业素材。官方来源：<https://apps.apple.com/us/app/glory-of-generals-3-ww2/id1535759278>。不包含 EasyTech 图片、模型、商标、肖像或第三方库。

## 战场

- 阿登 22×14 大地图，14 个据点；另有诺曼底突破战役。
- 尖顶六角格正确密铺，完整地图边界包含全部行偏移与边缘地格；绘制、点击、焦点、战果和缩放使用同一坐标；真实已缩放地格 Layout 提供滚动锚框，交战相关焦点取双方中点，避免窄屏裁掉一方战果。
- 原生 Canvas 组合低对比草土、低频地表起伏、耕地田块和八款山林/村镇资源；森林有针叶/混交疏林三种剪影，雪区有疏密区别。河流共享端点、宽度与切线；两侧真实河流夹住的城镇/道路保持水道连续，河源有自然端潭。
- 城镇接入真实相邻道路；只有河流格相对两岸均有公路/城镇时才画桥面、护栏与桥墩。桥梁仅为表现，不改变 river 成本、不新增免费通道。
- 八款通用盟/轴兵模之外，M10、M7、虎式与豹式有四款原创专属外观；M10 显示履带式歼击车而非轮式侦察车，但保留原 recon 规则。AL 蓝色实线 / AX 红色虚线环及字码共同识别阵营，不只依靠颜色；将领徽章显示姓名首字。
- 五段 HP 与独立移动/攻击槽区分四种行动状态；将领、军衔、断补给和战术状态保留。双资源都耗尽才为 spent。

## 操作

1. 顶部战役名打开战役菜单；资源带显示回合、目标进度和指令点，右端明确显示“结束回合”。宽屏另显示阵营与待命数。
2. 开局与重开默认把镜头放在真实存活双方距离最近的前线中点，不篡改规则焦点或单位状态。双轴拖动地图；右上放大镜选择战役/战术/细节缩放，重开按钮重新开始当前战役。
3. 点击友军选择，点击地格/敌军获得现有移动、攻击、接敌预览；鼠标主键预览、次键执行的原链路保留。动作坞“执行”同样调用规则状态机，不存在 UI 简化规则。
4. 选中单位后，底缘单一动作坞显示名称、HP、移动/攻击状态、待命防御与攻击/接敌/据点定位；行动全部耗尽时以短说明替代三颗无用的禁用按钮。可执行预览显示真实伤害/反击或移动成本；详细战斗预测在情报中查看。
5. 底缘“编队 / 据点”展开 AL/OBJ/AX 全量横向定位轨道：友军选择、敌军/据点聚焦，不误执行行动。“下一支”选择下一支仍可行动的部队。
6. “战术支援”按需展开编队摘要、战术命令、增援部署与图例；右上望远镜展开完整战场情报，面板标题栏可关闭。默认收起，不永久挤小地图。
7. 战况条显示当前操作反馈，情报保留战报、战线态势、据点压力、敌情反制、后勤结果与 AI 行动回放。普通战斗在原交战位置显示真实 HIT/RET、HP 前后与结论，随后淡出但保留规则结果。
8. 右上地图按钮开关“战区总览”（宽屏默认展开、窄屏默认收起）；AL 圆点、AX 菱形和据点方框表示真实战区。点按真实六角格只聚焦，不执行行动；空白和格外区域不误跳转。底部准星只把镜头送回前线，不改变选择。白框表示规则焦点，不冒充视口框。
9. 横屏高度不足 500pt 时用短顶栏/紧凑动作坞，总览不因宽度大而自动展开。游戏隐藏系统状态栏与非必要系统覆盖，保留安全区和所有操作入口；横屏仍是同一套地图和规则，不是截图缩放。

## 保留的规则

地形成本与兵种适性、六邻接、控制区、路线预览、攻击射程、兵种克制、夹击、反击、待命防御、将领与相邻协同、机动追击、炮兵弹幕/突破、士气、经验晋升、补给/断补给、据点奖励与休整、指令点、增援部署/整补、目标推进、期限与三星评价、轴心 AI、战线态势与敌方意图反制均继续由 `GameState` 管理。AI 复盘摘要中的关键事件先列占点，再按原有战果分数和事件序号排列；这不改变实际 AI 行动或时间线顺序。

v3.0 的批量地图提示只共享一次移动路线搜索，并与单格入口逐格等价测试；寻路进一步在单次只读查询中快照地格/存活单位/ZOC，保留 FIFO 与 tie-break，并由独立旧搜索逐路线对比；没有改变寻路、伤害或 AI 语义，没有跨回合缓存。

## 工程

Xcode 工程：`WW2Tactics.xcodeproj`；共享 scheme：`WW2Tactics`；iOS 17+，支持 iPad/iPhone。`ContentView` 只做根编排；导航投影、河岸几何、道路/桥梁计划、确定性地貌布局、静态地形、地图交互、兵模与战果各自独立。战役栏、单位动作坞与地图编排分离；原 5,044 行情报文件按七个领域拆分，保留规则入口。六个原创 PNG 随包离线使用，20 个 sprite 由 ImageIO 一次解码/裁格并复用，预算仍为 24 MB，不引入第三方库或复杂资产管线；完整提示词与来源见 `../md/art/v3.0-artwork.md`、`../md/art/v3.2-artwork.md`。

本轮人工要求：不做本地编译、测试、模拟器或截图，全部由 `main` 推送后的 GitHub Actions 执行。本机将来获准运行时只能使用 UDID 以 `FAC4325D` 开头的唯一模拟器，云端不受该限制。

## 云端验证

`WW2Tactics CI Results` 执行：静态检查、规则 smoke、Xcode build-for-testing、147 项真实规则/表现 XCTest，及两设备各 1 项真实横屏 UI 测试；同一 SHA 六图包含原四张竖屏和两张横屏战果。横屏由 XCUITest 的 XCUIDevice 旋转，验证结束回合按钮可点、M10 可见、情报抽屉真正开合，再导出两个相隔一秒的原始 app screenshot 附件；不旋转 PNG、不在 app 加强制方向钩子。默认态不预置战斗，战果用公开操作生成，不写假伤害。

每图检查尺寸、≥500 KB、战场亮度/可读比例、请求方向与实际像素方向一致，Vision 拒绝已知 Apple Intelligence 通知；竖屏有界重拍、横屏两个原始附件均须通过，不修图消除遮挡。记录 device/runtime/UDID、场景与 SHA-256；结果包包含独立阶段/规则测试/UI 测试 JUnit、manifest、summary、日志、xcresult 和六图，仍需逐图视觉检查。云端两个现有模拟器并行启动以减少首启迁移等待，实际测试/截图顺序执行，不创建新设备。

本轮单智能体直接实现并核对云端结果，不按 A/B/C 调度。首轮 `16d499d` / run `40077251421`：147 项真实测试通过、原四图通过；两张横屏仍为竖向像素画布，门禁正确失败，未宣称完成。现改为 XCUITest 真实旋转和取证，目标 147 项规则/表现 + 两设备各 1 项 UI 测试，以最新 SHA 六图/结果包验收。测试规范见 `../md/test/test.md`，流程见 `../md/flow/flow.md`，历史见 `../update_log.md`。

## 已知边界

兵模与地貌是原创透明预渲染资源，不是商业游戏贴图或实时 3D 引擎；四款命名装备之外仍用通用模型。新 VisualUITests 只覆盖旋转、战果画面和情报开合，不证明地图触屏命令、鼠标、拖动、VoiceOver、全部字号或全部缩放实测；Vision 只识别已知系统通知，不代替人工检查。长期仍需提升美术、更多战役与存档，本轮不擅自扩展玩法。
