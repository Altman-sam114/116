### 目标、实现和边界

1. 用内置 imagegen 生成四份原创资源：车辆 2×2 atlas（盟/轴坦克、盟/轴轮式侦察车）；军队 2×2 atlas（盟/轴三人步兵、盟/轴火炮）；地貌 2×2 atlas（针叶林簇、岩石山脊、欧洲村镇、冬季针叶林）；低对比可平铺草土底材。透明图必须保留真实 alpha；全部是统一左上光源、约 55 度俯视的细节预渲染风格，无文字/网格/旗帜/商标/纳粹符号。不要生成整张 UI 冒充实现。
2. 只把最终生成的四个 PNG 复制进项目 `BattlefieldArt/`，记录完整提示词、来源、格位、尺寸和摘要。禁止 Python/CLI 偷换图像生成、下载 EasyTech 资产或引入付费 API 密钥。由原生 ImageIO 一次解码、按固定 atlas 格裁出 CGImage 并复用，无逐格磁盘读取，无计时器和随机渲染；全包资源预算 24 MB。
3. 新建小型 artwork 资源读取边界，兵模 renderer 删除旧的大块几何绘制，四类八款实体在真实地图尺寸可辨；小阵营环不变成大棋子底座，HP、M/A、AL/AX、将领/rank/CUT/战术状态保留。地图兵模适当增大但不得遮住邻格和点击框。
4. 地貌 renderer 用连续纹理底材和透明树丛/岩脊/村镇替换三角山、重复房子和锥形树。雪地按真实 snow tile union 柔化边缘，不再一格一块白色纸片；树林/岩体有稳定位置/尺度变化和接地阴影，不用运行时随机数。道路与河道仍来自真实邻接，河流通过共享边中点的曲线连续连接，取消双线管道观感；不得修改地图与规则来迁就美术。
5. 战争 HUD 统一成窄幅金属指挥带、小型贴边工具和清楚的情境命令坞，保持结束回合、战役、缩放、情报、轨道、支援、增援与真实执行入口；仍以地图操作为主体，不新增营销标题或多层玻璃卡片。
6. 针对云端/交互开销，可将 movementRoutes 的地格、存活单位和 ZOC 计算限定在一次只读查询快照内；FIFO 顺序、成本、tie-break、路线坐标和全部状态保持。禁止跨回合缓存。只有补独立旧算法 oracle、逐路线对比真实战役后才允许此优化；不得通过少跑测试提速。

## 6. 数据流、状态流与性能边界

```text
GameState 唯一规则事实源
  -> 只读地图布局/地表数据 -> 静态 terrain renderer
  -> 只读单位/地格/预览/战果 -> 交互地格、兵模、战术 overlay、边缘 chrome
用户操作
  -> 现有 GameState select/focus/handleTap/handlePrimaryAction/handleSecondaryAction/execute/endTurn
  -> Published 状态 -> 原始规则结果和 UI 更新
```

- Inspector、支援面板开关、地图缩放仍是本地 UI 状态，不写进 `Scenario` 或 `GameState`。
- focus、快捷定位和 rail 只改变既有焦点/选择，不能隐式执行移动或攻击；继续用坐标稳定 ID 和 `ScrollViewReader`，缩放后仍定位正确。
- 战果层从 `latestCombatResult` 的真实 attacker/defender 坐标和伤害读取；不得用当前 selected/focused 猜测已结束战斗的位置。
- 新静态 renderer 输入尽可能为明确小型值，避免扩大 `EnvironmentObject` 广播；拆分复杂 ViewBuilder 以控制编译成本。
- 现有 `mapActionHint` 在逐格读取时可能反复求路线。Agent X 已据源码确认逐格重复 Dijkstra，并批准一个有界优化：`GameState` 内批量只读预览复用同规则，不改变公式，并为所有 tile 断言批量与原入口等价。仅共享已有移动路线结果，不能演变为整套寻路、AI 或缓存重写。
- 不在 SwiftUI `body` 中引入全局缓存、异步状态回写、网络、随机纹理或未受控 timer；不把复杂 Path 全部塞回 `ContentView`。
