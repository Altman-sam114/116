# v2.20 紧凑编队与目标轨道

## 背景

`ObjectiveJumpDock` 当前用一个 `ScrollView(.horizontal)` 包住单一 HStack，内容顺序是全部 `mapFriendlyFocusUnits`、全部据点、全部 `mapEnemyFocusUnits`。`UnitFocusButton` 与 `ObjectiveJumpButton` 又由名称和 padding 决定宽度。在阿登大编队中，友军段独占首屏，玩家必须横向滑过整段友军才能看到据点和敌军；不同名称长度还会改变单项宽度和整体滚动位置，不符合战棋界面“模型先认、状态快扫、三类目标随手定位”的操作目标。

本轮应把底部轨道从一条无边界内容流重构为友军、据点、敌军三个同时可见的有界段。每段保留自己的完整数据和横向滚动能力，首屏至少露出一项；单项使用稳定宽度，以军械模型或据点旗标为第一视觉信号，并在不打开 Inspector 的情况下读到 HP、移动/攻击消耗和据点归属。

## 目标

1. 将 `ObjectiveJumpDock` / `ObjectiveJumpStrip` 重构为 AL 友军、OBJ 据点、AX 敌军三个并列分区；regular 和 compact 宽度下三段都必须同时可见。
2. 每个分区内部独立横向滚动，继续承载全部友军、全部据点和全部敌军，不裁剪数据、不只展示固定前 N 项。
3. `UnitFocusButton` 使用统一稳定宽度和至少 44pt 点击区，军械徽章优先于长名称，并显示紧凑 HP、MOVE/ATK 状态轨道。
4. `ObjectiveJumpButton` 使用统一稳定宽度和至少 44pt 点击区，旗标/归属优先于长名称，并清楚区分盟军、轴心和中立据点。
5. 保留友军选择、敌军定位、据点定位的现有 `GameState` action、排序和地图自动滚动链。
6. 所有可视短码、图标和压缩文字都提供完整 VoiceOver label/value/hint；颜色不是区分阵营、归属、完成状态或焦点的唯一方式。
7. 在既有 `selected-combat-impact-steady` 云端截图中，底部无需滑动即可同时看见友军、据点和至少一个敌军项目，且不明显增加轨道高度或遮挡地图。

- 不修改 `BattlefieldMap.swift`、单位地图棋子、战果叠层、右上动作坞、支援甲板、地图 frame、缩放、坐标、marker、命中或手势。
- 不修改 workflow、CI 参数、截图场景、Xcode project，不新增测试 target、第三方库、网络依赖或资产管线。
- 不新增分页状态、选项卡、展开/收起状态、缓存数组或 View 内规则排序副本。
- 不触碰、暂存或提交用户已有的 `AGENT.md` 删除、`WW2Tactics.xcodeproj/project.pbxproj` 修改、`update_log.md` 修改和 `md/unity分析/` 未跟踪目录。

## 当前架构依据

- `MapCommandCenter` 已把 `ObjectiveJumpDock` 固定叠放在地图工作区底缘；本轮只重构 Dock 内部，不移动外层锚点。
- `game.mapFriendlyFocusUnits` 已按“仍可行动优先、距当前锚点距离、兵种和名称”稳定排序；`game.mapEnemyFocusUnits` 已按距锚点距离、兵种和名称排序。View 必须直接消费这两个数组。
- 据点当前由 `objectiveSort` 按轴心、中立、盟军及名称排序；本轮可保留该既有纯展示排序，但不得发明新的战略优先级或写回模型。
- 友军按钮现有 action 为本阵营 `game.select(unitID:)`，敌军按钮为 `game.focus(unitID:)`，据点按钮为 `game.focus(coordinate:)`；这些 action 与 `focusedCoordinate` 的地图滚动链已经存在。
- `UnitShapeBadge` 已表达兵种、阵营、将领、军衔、补给、战术状态和 complete 降权；`MiniHealthBar` 已提供稳定五段 HP 表现，可在不复制 HP 规则的情况下复用。
- `BattleUnit.hasMoved` / `hasAttacked` 和 `hpRatio` 是现有事实字段。紧凑轨道只能显示这些值，不推导可达格、攻击目标或新的 ready 规则。
- SwiftUI 固定轨道应使用明确的容器高度、稳定 item 宽度和有界分区宽度，避免名称、焦点描边、状态变化或滚动内容改变 Dock 尺寸。

## 实现步骤

1. 在 `BattlefieldChrome.swift` 重构 `ObjectiveJumpDock`：保持现有底缘位置和 `MapHudBackground`，减少无效 padding，给内部轨道明确稳定高度，避免 `GeometryReader` 无限扩张地图 overlay。
2. 将 `ObjectiveJumpStrip` 从“单 ScrollView + 单 HStack”改为 AL / OBJ / AX 三个并列、有视觉边界的 section。建议友军约占可用宽度 38%-42%、据点约 24%-28%、敌军占剩余宽度；具体比例可按当前 regular/compact 断点调整，但最窄支持宽度下每段仍至少容纳 section 标识和一个 44pt 项目。
3. 每个 section 使用短而固定的非滚动标识（军械/旗帜图标、`AL` / `OBJ` / `AX` 与数量），右侧或下方才是该段自己的横向 `ScrollView`。三个 section 之间用细分隔线、实/虚线或不同图标区分，不能只靠蓝/黄/红颜色。
4. 每段继续 `ForEach` 完整现有数组。友军直接使用 `game.mapFriendlyFocusUnits`，敌军直接使用 `game.mapEnemyFocusUnits`，据点继续使用 `game.objectiveTiles.sorted(by: objectiveSort)`；不得 `prefix`、截断或复制排序到 `@State`。
5. 如新增 `ObjectiveJumpSection` 一类小 View，输入只包含标题、图标、数量、视觉色和已构造的内容；不要把 GameState 规则塞进通用容器。避免 `AnyView`，避免在 `body` 做昂贵重复过滤。
6. 将 `UnitFocusButton` 设为统一固定宽度：建议 regular 82-92pt、compact 70-80pt，最终以云端不溢出且三段可同屏为准；按钮总高度至少 44pt，焦点描边必须 overlay 绘制，不能让选中态改变尺寸。
7. 单位按钮采用“模型优先”的两层布局：首要位置显示 `UnitShapeBadge`；名称只占稳定单行区域并允许合理缩放/截断；下方使用 `MiniHealthBar(unit.hpRatio)`、HP 数字或短值，以及移动/开火图标。移动/开火未消耗与已消耗必须同时有图标形态差异，例如箭头/瞄准与 checkmark，不能只换颜色。
8. 单位按钮不需要再次展示所有已包含在徽章内的长标签。Commander、军衔、补给和战术状态继续由 `UnitShapeBadge` 表达；complete 仅当 `hasMoved && hasAttacked` 时降权，与 v2.18 语义一致。
9. `UnitFocusButton` 保留 action 原样：`unit.faction == game.activeFaction` 时 `select(unitID:)`，否则 `focus(unitID:)`。不要用手势替代 Button，不要直接写 selected/focused 属性。
10. 将 `ObjectiveJumpButton` 设为与单位按钮同族的固定宽度和至少 44pt 点击区。用更大的旗标/据点符号作为主视觉，使用 `AL` / `AX` / `NEU` 文字或不同 stroke 形态表示归属，名称放在稳定单行区域；焦点黄框 overlay 不改变尺寸。
11. `ObjectiveJumpButton` 继续只调用 `game.focus(coordinate:)`。保留据点真实名称和归属，不把名称截断结果用作 accessibility 文案。
12. 为 Unit 按钮提供组合 VoiceOver：动作“选择”或“定位”、完整单位名、阵营、兵种、HP 当前/最大、移动已用/可用、攻击已用/可用、补给、战术状态、军衔和是否有将领。可视模型与状态装饰设为 accessibility hidden，避免重复朗读。
13. 为 Objective 按钮提供组合 VoiceOver：定位、完整据点名、当前归属、坐标和是否为当前焦点；section 标识应读出类别和总数。必要时增加简洁 hint，说明激活后只选择/定位地图，不执行命令。
14. 使用语义字体或现有可缩放字体，长名称单行 `lineLimit(1)` 并设置合理 `minimumScaleFactor`；不要用小于当前 9pt 的新文字解决布局。可视名称受限不影响 VoiceOver 完整信息。
15. 同步 README、flow、flowchart、test 和 prompt README，说明三段轨道只读既有数组并转发现有 action；严格保持 `update_log.md` 不动。

## 建议布局基线

- Dock 总体：维持单层地图底缘工具轨，不新增第二排大卡；包含外边距后的高度应接近 v2.19，不能明显侵占更多六角格。
- Section 标识：固定窄列或短标题行，显示 `AL 11`、`OBJ 14`、`AX 11` 一类类别与数量；数量取现有数组 count。
- Unit item：稳定宽度、最小 44pt 高；模型占主要识别面积，名称是次级信息，HP 和 MOVE/ATK 是底部扫描轨。
- Objective item：与 unit item 相同高度和接近宽度；旗标、归属短码和焦点态优先，长地名不播宽项目。
- regular 截图：三段都应露出多个或至少一个完整 item，并让后续半露 item 暗示各段可独立横向滚动。
- compact：允许每段只露一个 item，但不能把任一类别完全挤出或退回单一长 ScrollView。

## 风险和禁止项

- 禁止继续使用一个“全部友军 -> 全部据点 -> 全部敌军”的单一横向内容流，否则无法满足三类首屏同时可见。
- 禁止通过只显示前 N 个单位/据点、删除名称、删除状态或删除敌军来制造紧凑效果。
- 禁止让 GeometryReader、滚动内容或 Dynamic Type 撑高 Dock；固定格式轨道必须有稳定高度与响应式宽度约束。
- 禁止把可视 item 缩到 44pt 以下，或只扩大外层 contentShape 却让相邻点击区域重叠。
- 禁止使用 `onTapGesture` 替代 Button，禁止绕过 GameState 直接写选择或焦点状态。
- 禁止在 View 里复制 ready、补给、威胁、攻击或目标推进规则；只展示现有字段和集合。
- 禁止只靠蓝/黄/红表达阵营、据点归属、焦点或移动/攻击消耗；必须配合模型、短码、图标、stroke 或 checkmark。
- 禁止修改 CI 场景或放宽 500 KB 门禁，禁止用本地截图冒充云端证据。
- 禁止覆盖、重置、回滚、暂存或提交用户和其他 Agent 的未提交改动。
