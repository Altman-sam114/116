# v2.57：战区指挥台视觉重构

## 版本与依据

- 版本：`v2.57`，基于 `origin/main` 最新 `v2.55` 云端通过提交 `db2878f1dc7459a549cf72d0945f2ce5159a90bc` 递增。
- 参考：EasyTech《Glory of Generals 3: WW2》App Store 截图（只读参考，未引入第三方资产）。

## 背景与目标

当前规则和六角格地图已经完整，但外围 chrome 偏暗、信息层级分散，地图不像一个可持续操作的战区。本轮将 SwiftUI 表现层重构为“战区指挥台”：顶部资源/回合带、连续地形战区、蓝红阵营单位环、底部支援甲板和更明确的作战状态层。

目标是提升地图可读性、单位辨识度和战棋指挥感。所有交互仍经 `GameState`，所有状态只读派生到 View；不改变规则、地图坐标、输入和命令时序。

## 非目标

- 不修改 `GameState`、`GameModels`、测试规则、AI、战斗数值或地图尺寸。
- 不引入图片、网络、第三方库或新的持久化状态。
- 不做静态宣传页；地图仍是首屏和主要交互。

## 实现范围

- `ContentView.swift`：战区背景和工作区外框采用温暖军用地图色、渐变暗角和内嵌地图边界。
- `BattlefieldChrome.swift`：顶部重构为两层 War Ledger（标题/战役/回合资源 + 阵营/目标进度），MapToolbar 增加战区坐标与作战状态提示。
- `BattlefieldMap.swift`：MapGridBackdrop 增加低对比测绘网格、等高线和边缘暗角；保持 terrain、tile frame、命中测试与 overlay zIndex 不变。
- `BattlefieldUnitViews.swift`：地图单位底座强化蓝/红阵营环、内圈高光和状态刻度，保持既有单位模型与无障碍摘要。
- `BattlefieldTheme.swift`：增加仅表现层颜色 token。
- 同步 README、flow、flowchart、test、update_log、prompt README。

## 验证与云端流程

本机不运行 Swift、Xcode、模拟器或截图，仅做 `git diff --check`、范围检查和文档检查。改动提交到 `main` 并 push `origin/main`，由 GitHub Actions 运行 static、Rules smoke、Xcode build-for-testing、regular screenshot。验收必须下载最新 exact artifact 到 `/private/tmp/ww2tactics-c-review-<run_id>/`，核对 manifest 的 commit/run/attempt 并查看 PNG。

## 验收标准

- 视觉上形成清晰的顶部指挥带、中心六角战区、底部支援甲板；地图操作仍占主要面积。
- 地图背景有低对比测绘纹理，不遮盖六角格、道路、河流和战术标记。
- 友军单位环为蓝色、敌军为红色，单位模型、HP 条、军衔与状态牌仍可读；选中态暖金仍最高优先级。
- `GameState` 和模型无 diff，输入/geometry/contentShape/zIndex 保持；不增加 View 状态或昂贵 body 计算。
- 云端 exact artifact 的 static、Rules smoke、build-for-testing、regular screenshot 均通过；XCTest skipped 必须如实记录。

## 风险与禁止项

- 颜色不可成为唯一阵营信号，保留模型形状、边框和文字；遵守 Dynamic Type、VoiceOver、Reduce Motion。
- 测绘纹理必须低对比、无 hit testing；不能用全树 opacity 掩盖布局问题。
- 不得把云端新结果用旧 artifact 或本地截图替代。
