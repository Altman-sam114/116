## 目标

1. regular 战场中，道路首先读作服从周围地表的低对比路基，其次才读出窄主路面。
2. 使用克制的边缘高光或细 rim 保留路面厚度；不得形成明亮中心线、发光管线或重新出现逐格虚线。
3. 保持既有主干、端点、分支、路口、长环路、地图边缘连接和孤立道路短笔触清楚可追踪。
4. 道路的视觉优先级低于据点、军械、HP/行动轨道、selected、marker、HIT/RET、HUD 和 `AL / OBJ / AX` rail，并与 v2.47-v2.50 的白昼地表、五类材质、河道和蚀刻边界协调。

## 架构依据与最小允许边界

实际源码已把道路网络和材质分开：

- `RoadConnectionNetwork` 只负责稳定选择 canonical 道路边并投影 paired half-path。
- `HexMapView` 把结果作为 `terrainConnectionDirections` 传入 `TerrainTexture`。
- `TerrainTexture.connectionPath(in:)` 负责把既有方向转换为中心到端点的 `Path`，并为孤立道路生成既有短笔触。
- `TerrainTexture.connectionLayer(in:)` 当前让 road 进入通用 shadow / 主体 / highlight 三笔绘制；材质调整可以只在这里分流到 road-only helper，并复用完全相同的 `Path`。

因此本轮采用更小实现范围：

- 唯一允许修改的 Swift 文件是 `WW2Tactics/WW2Tactics/BattlefieldMap.swift`。
- 唯一允许修改的源码区域是 `TerrainTexture` 内的 road-only connection/material 分支：可在 `connectionLayer(in:)` 增加 `.road` 分流，并新增私有 `roadConnectionLayer(_:)` 与仅供它消费的颜色/线宽常量。
- `BattlefieldTheme.swift` 默认冻结，不新增 road token；当前源码可在 `TerrainTexture` 私有 road-only 范围完成目标，无需扩大到第二个 Swift 文件。
- 若实现时发现必须越过上述区域，Agent B 必须停止并报告，不得自行扩大到网络、路径、Theme 全局 token 或 `TerrainKind`。
