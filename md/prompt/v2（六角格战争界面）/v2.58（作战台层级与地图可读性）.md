# v2.58（作战台层级与地图可读性）

## 版本分配依据

当前 `origin/main` 最新版本为 v2.57，且 run 36235971104 / attempt 1 已通过云端 artifact。v2.58 是同一六角格战争界面阶段的下一轮表现层迭代。

## 背景

v2.57 已建立 War Ledger 顶部指挥带、测绘底材、单位阵营环和战区工作区。最新云端 regular 截图显示六角地图和单位模型已可用，但地貌明度变化过大、单位与道路的对比不足，顶部状态信息在竖向设备上显得过小，作战台与地图主体的层级仍不够像 EasyTech 风格的持续战场。

## 目标

- 收敛平原、雪地和森林底材的明度与连续晕染，让单位、据点、道路和战斗标记在地图上更清晰。
- 提高顶部战役标题、回合资源与战区 ribbon 的信息层级，保持单行和紧凑布局。
- 强化地图工具栏的“作战地图”身份，同时保留现有缩放、重开和无障碍语义。
- 继续保持六角格、单位模型、底部 AL/OBJ/AX rail 和战斗结果为核心交互。

## 非目标

- 不修改 `GameState`、`GameModels`、AI、移动、攻击、胜负或任何规则计算。
- 不新增网络依赖、图片资产、第三方库、缓存状态或持久化状态。
- 不重写地图几何、命中区域、ScrollView、命令 action 或 VoiceOver 文案结构。
- 不跑本机测试；由 GitHub Actions 负责 smoke、build-for-testing 和截图。

## 架构依据

`BattlefieldTheme.swift` 只提供表现层 token；`BattlefieldChrome.swift` 负责顶部指挥带、地图工具栏和地图 HUD；`BattlefieldMap.swift` 的 `HexTileView` 只读取既有地形 token。所有命令仍必须转发到 `GameState`。

## 实现步骤

1. 调整地图纸张、地貌连续层与边界 token，降低白色洗底并保留道路/河流/据点的层级。
2. 提升 `CommandTitle`、`StatusChip` 和 `WarLedgerSituationRibbon` 的字号、间距和对比度，确保窄屏仍可压缩。
3. 调整 `MapToolbar` 的标题表达和背景层，不改变 Picker 与重开按钮 action。
4. 运行 `git diff --check`，提交到 `main` 并 push，等待云端 workflow。
5. 下载唯一最新 artifact，核对 manifest 的 commitSha、runId、runAttempt、截图和 JUnit。

## 验收标准

- 六角地图、单位、据点、道路、河流和战斗结果在 regular 截图中保持可读。
- 顶部战役/回合/资源信息层级提升，地图工具栏仍可操作。
- manifest 的 branch 为 main，commitSha 与 origin/main 完全一致，run/attempt 与 artifact 名称一致。
- static、smoke、build-for-testing、screenshot 和 JUnit 通过。
