# v2.36 补给线覆盖降噪

## 版本号与分配依据

- 版本号：`v2.36`
- 分配依据：v2.35 已由 `origin/main` commit `c0f15815bcd1129e9216506e2bce2db2902a8741`、GitHub Actions run `30324158129`、attempt `1` 和 artifact `ww2tactics-ci-v2.35-main-c0f1581-run30324158129-attempt1` 完成云端结构、规则、构建和截图验收。v2.35 PNG 已确认暖金/象牙选中实体底座、抬升、接地阴影、HIT/RET 和交战结论清晰，但同时暴露出补给线以每格绿色粗胶囊和整格绿色粗边框重复表达、横跨地图并压过地貌与兵模的问题，因此递增 v2 小版本收敛补给线覆盖。

## 背景

当前 `HexMapView` 从已选单位只读调用 `game.supplyLineTiles(for:)`，并将结果传给 `HexTileView.isSupplyLine`。`HexTileView` 随后绘制 `SupplyLineMarker`，且在 `borderColor`/`borderWidth` 中为每个补给格设置高对比绿色整格边框。`SupplyLineMarker` 目前是宽约 56pt、高 10pt 的绿色胶囊，连续补给格因此变成醒目的重复色块；它还会与白昼地貌、道路、河流、单位底座、选中焦点和其他战术 marker 争夺视觉层级。

EasyTech《将军的荣耀3》式地图应让地貌和实体兵棋先被读到，补给线作为后勤信息以低对比、连续的战术通道提示存在。v2.36 只收敛这一层表现，不改变补给规则或用户可用的补给信息。

## 目标

1. 将补给线从“每格绿色粗胶囊 + 每格绿色粗六角边框”收敛为更细、更低对比、能在相邻六角之间读作连续通道的视觉表达。
2. 优先使用与既有六角邻接方向一致的细线/窄带连接；可从当前 `Set<HexCoordinate>` 和 `HexCoordinate.neighbors` 在 View 内只读派生连接方向，不保存新的规则状态。若采用单格细带，也必须避免大面积胶囊和端点断裂感。
3. 让地貌纹理、道路/河流、单位军械模型、暖金选中焦点、路线和高优先级命令 marker 保持第一层级；补给线只能作为低对比底层信号，不得覆盖或压过它们。
4. 继续在普通地图态显示补给路径；攻击焦点态的现有降噪规则保持不变，不能因重构而在 `.attack` 状态重新铺满补给覆盖。
5. 保持地图无障碍摘要、补给面板/动作坞中的 `SUP`/`CUT` 文案和现有补给线计数语义；装饰线继续不拦截输入且从 VoiceOver 树隐藏。
6. 保持响应式尺寸和 Dynamic Type/Reduce Motion 约束：细线的 frame、旋转、端点和阴影不能因字体或 viewport 改变而导致六角 tile、命中路径或布局跳动。

## 非目标

- 不修改 `GameState.supplyLineTiles(for:)`、`supplyState(for:)`、`SupplyState` 的 `supplied`/`isolated`（`CUT`）语义、补给来源搜索、敌军阻断判定、移动/攻击倍率或战役数据。
- 不修改 `GameModels.swift`、单位位置/HP/行动状态、目标归属、AI、战术命令、地图坐标或规则测试行为。
- 不修改六角 tile 的 `frame`、`contentShape`、`Hexagon` 命中路径、`HexInputReader` 三种输入、`position(for:)`、滚动范围、缩放计算或 tile/单位/交战叠层 `zIndex`。
- 不修改 v2.35 暖金 `BattlefieldTheme.selectedPiece`、`SelectedUnitGroundHalo`、选中棋子 3pt 抬升/接地阴影和四角准框；不修改 v2.34 HIT/RET 单行铭牌、交战轴线、战果 phase 或 steady-state 启动桥接。
- 不删除补给线入口、图例、侧栏 `SUP`/`CUT` 信息或 VoiceOver 摘要；不以地图视觉变更替代规则或文字反馈。
- 不新增图片、第三方库、网络依赖、动画状态、持久化字段、View 中的规则计算或复杂资产管线；不修改 workflow、CI 截图参数或 Xcode project。

## 当前架构依据

- `GameState.supplyLineTiles(for:)` 是补给路径唯一事实源：它从当前单位到己方据点做可通行六角 BFS，并在没有可达来源或单位被摧毁时返回空集合。View 只能读取该 `Set<HexCoordinate>`，不得复制算法或推断 `SupplyState`。
- `GameState.supplyState(for:)` 仍以补给线是否为空派生 `.supplied`/`.isolated`；面板和动作坞继续通过既有入口读取 `SUP`/`CUT`、补给格数量及说明。
- `HexMapView` 当前已计算 `supplyLine`，并将 `isSupplyLine` 传给每枚 `HexTileView`。本轮可在 `BattlefieldMap.swift` 内从同一只读集合派生相邻补给坐标/连接方向，但不能新增 `@State`、`@Published` 或规则缓存。
- `HexTileView` 的既有优先级顺序必须保留：selected/命令/路线/火力与态势 marker 优先于普通补给线；补给线不应重新夺取高对比 `borderColor`/`borderWidth`。
- `BattlefieldTheme.swift` 是跨模块视觉 token 所在处。如需要统一的低对比补给色，可增加纯视觉 `supplyLine` token，颜色应与白昼地表、盟军蓝环、轴心红环、红色威胁和暖金选中态区分；不得把该 token 传入规则层。
- `SupplyLineMarker` 只负责装饰绘制，必须继续 `.allowsHitTesting(false)`、`.accessibilityHidden(true)`；`HexTileView.accessibilityLabel` 及单位的组合摘要不能被拆成重复朗读。

## 实现步骤

## 验收标准

1. `--ci-selected-combat-impact-steady` 云端 PNG 能看到一条或多条补给通道，但补给格不再被每格绿色 2pt 粗边框和高 10pt 胶囊占满；补给视觉透明度明显低于 v2.35，地貌纹理、道路/河流和军械模型优先可读。

## 风险和禁止项

- 禁止修改或复制 `GameState.supplyLineTiles(for:)` 的 BFS、敌军阻断、据点来源和空路径语义；禁止在 View 中判定 `SUP`/`CUT`、补给损耗或任何战斗数值。
- 禁止以更亮、更粗、更大面积绿色补偿连续性；补给线是低优先级通道提示，不得压过白昼地貌、道路/河流、单位、选中态、路线、攻击、态势或复盘 marker。
- 禁止让补给边框重新夺取整格高对比优先级，禁止用每格独立胶囊/圆徽重复同一信号；颜色不能成为唯一可访问编码。
- 禁止改动 tile frame、contentShape、`HexInputReader`、zIndex、坐标、缩放、滚动、输入 action、规则状态、战果 phase 或 CI 截图门禁。
- 禁止新增不可测试的状态、随机纹理、动画计时、第三方依赖、图片/网络资产或本地测试伪造；不得把旧 v2.35 artifact、checkout 自带报告或本地截图当作 v2.36 证据。
- 云端失败时不得回滚 `origin/main`；由 Agent B 在 `main` 追加针对性修复 commit，Agent C 重新下载最新 artifact 验收。
