## 背景与残余证据

`WW2Tactics/WW2Tactics/BattlefieldMap.swift` 的 `RoadConnectionNetwork` 从 `.road` 坐标构造 canonical 候选边，Kruskal 主干保留桥接边和端点，再按每个连通组件添加一条确定性回边；`TerrainTexture.connectionPath` 将所选方向投影为两端 paired half-path，shadow、主体和 dashed highlight 共用该路径。该设计已消除 v2.36 的双侧重复 lattice，但当前回边选择只按端点候选度数和坐标排序，可能优先闭合很短的三角环，使密集路口看起来像多个小三角而不是一条连续的战区公路。

本轮目标是改善“哪一条回边代表环路”的视觉选择，不增加第二套地图连通性，也不改 road tile 的规则可通行性。应优先保留长、低分叉、可追踪的环路闭合；若组件没有合适的替代回边，宁可保留现有一条确定性回边，也不能重新画回每格六向线或把所有候选边都绘制出来。

## 目标

1. 保持每个道路连通组件的主干连续：所有桥接边、端点和必要的低度道路节点继续可见，任何有环路的组件仍至少保留一条真实回边。
2. 细化回边选择的稳定排序，使回边优先闭合较长、较少经过高阶路口的环路，避免在存在替代路径时优先闭合最短三角；同一坐标和同一地图状态每次渲染结果必须一致。
3. 明确回边 quota 不变量：`cycleRank == 0` 的组件不添加回边；`cycleRank > 0` 的组件最多添加一条额外回边（`backEdgeQuota <= 1`），总边数不超过 `vertexCount - 1 + 1`。不得因为地图尺寸、viewport、Dynamic Type、选中态或道路数量临时增加 quota。
4. 继续使用 canonical 无向边（方向 `0/1/2`）并向两端投影一次 paired half-path；道路 shadow、主体和高光共用该路径，孤立道路保留 q/r 确定性短中心笔触。
5. 保持道路视觉密度低于 v2.36 lattice：不恢复重复半边、不绘制每格完整六向中心辐射、不出现同一无向边多次覆盖；同时让阿登与诺曼底的直路、分支、环路、边界和孤立格都能读成连续道路。

- 不修改 `HexTileView` tile frame、坐标、`contentShape`、`HexInputReader`、ScrollView/ScrollViewReader、焦点定位、marker、单位模型、补给线、HIT/RET、zIndex、VoiceOver 或地图工作区。
- 不修改 `ObjectiveJumpDock`、AL/OBJ/AX 轨道、`ForceRibbon`、compact/Dynamic Type 文案、支援甲板或任何已验收的 v2.38/v2.39 rail 表现；rail 只做回归检查。
- 不把道路连接改成 `GameState` 路径、BFS、移动路线或新的可发布规则状态；不引入随机数、网络/图片资产、第三方库、workflow/Xcode project 改动。
- 不把“保留环路”实现为保留全部 candidate edges；不得用 `prefix`、分页或错误排序处理地图/道路数据，也不得回退 v2.37 的 `ForEach` value collection/type inference 修复。

## 当前架构依据

- `RoadConnectionNetwork` 是 `BattlefieldMap.swift` 内的纯表现 helper：`candidateEdges` 只从 `.road` 同类邻接和方向 `0/1/2` 生成 canonical `RoadEdge`；`RoadDisjointSet` 只为生成主干和连通组件服务；`directionsByCoordinate` 最终供 `HexMapView` 的 `TerrainTexture` 读取。
- 当前 v2.39 先选 Kruskal 主干，再在 `backEdgesByComponent` 中每个有回边组件选择一条 edge；问题集中在回边排序，而不是 `GameState` 或路线规则。
- `TerrainTexture.connectionPath(in:)` 只读取 `connectionDirections`，对每条方向画中心到边界的半路径；连接层 `shadow`、road body 和 dashed highlight 使用同一路径并关闭 hit testing。
- `HexMapView` 仍从 `game.tiles` 构造 `roadConnectionDirectionsByCoordinate`；保持显式 `[TerrainTile]` value collection 和现有 `ForEach` 结构，避免 v2.37 已修复的 SwiftUI Binding overload 类型推断回归。
- `BattlefieldChrome.swift` 的 AL/OBJ/AX rail 在本轮只读回归；不得借道路任务修改 section 比例、固定项尺寸、Dynamic Type 或定位 action。

3. 保持 Kruskal 主干的稳定坐标排序；为非树 candidate 计算其在主干上的只读路径长度或等价的稳定环路质量分数，优先选择闭合路径较长、端点度数较低、较少制造三路以上短三角的 edge。所有排序 tie-break 必须使用 q/r/direction，禁止随机或依赖 Set 遍历顺序。
