# v2.16 命中冲击与战果出现节奏

## 版本号与分配依据

- 版本号：`v2.16`
- 分配依据：v2.15 已由 `origin/main` commit `e614fa5b156beb687c2e35d03732e7426b3d4a37`、GitHub Actions run `30077809656`、attempt `1` 完成云端验收；对应 artifact 为 `ww2tactics-ci-v2.15-main-e614fa5-run30077809656-attempt1`。攻击预判和真实结算已经统一为 M10 `RET -7 / 64 -> 57`、目标 `HIT -21 / 64 -> 43`，本轮可在不碰规则数值的前提下优化开火后的地图反馈节奏。

## 背景

v2.14-v2.15 已建立可信的攻击闭环：`GameState.attack` 生成带双方执行坐标的 `latestCombatResult`，`CombatResolutionOverlay` 在原交战位置显示 HIT、RET、双方 HP 前后与“交火/压制/击毁”。当前叠层从出现开始就是完整固定态，缺少 EasyTech 风格的命中瞬间和信息先后层次；玩家能读懂结果，但感受不到“开火已经落点、伤害已经结算”的短促确认。

现有 CI 会在 app 启动后每隔 6 秒尝试截图，瞬时动画到截图时必然已经结束。不能通过延长生产动画、循环播放或写死测试画面来骗取证据，因此本轮必须同时设计：正常启动的一次性克制节奏，以及只冻结同一真实战果最终阶段的 deterministic CI steady-state。

## 目标

1. 每个新的 `CombatResultSummary.id` 只播放一次短促的“命中冲击 -> 战损牌 -> 交战结论”表现序列。
2. 防守方交战格先出现克制的冲击环、断续冲击线或碎片刻线，再出现 `HIT` 战损牌；存在真实反击时，随后出现 `RET` 战损牌；最后出现“交火/压制/击毁”标签。
3. 动画只改变表现层的透明度、轻微缩放和不超过数点的位移，不移动地图、不摇晃镜头、不改变单位 frame、六角坐标或输入。
4. 完整复用 `latestCombatResult` / `CombatResultSummary` 的坐标、伤害、HP 和结论，不在 View 重算或解析规则。
5. Reduce Motion 下取消冲击扩张、缩放和位移，直接或仅用短透明度过渡呈现完整稳定结果。
6. CI 使用真实公开操作链生成战果，并稳定截图到“最终结果 + 静态冲击残迹”证据态；CI 模式只控制表现阶段，不写死 M10、伤害、HP、坐标或伪造 summary。

## 非目标

- 不修改 `GameState.swift`、`GameModels.swift`、伤害、反击、经验、晋升、士气、选择轮转、结果清理或任何 AI/回合规则。
- 不给 `GameState`、`CombatResultSummary` 或其他规则模型增加动画 phase、时间戳、计时器或 CI 字段。
- 不自动清除 `latestCombatResult`，不实现本轮之外的战果消退策略。
- 不加入镜头震动、地图位移、单位位移、粒子系统、声音、触觉、位图素材、第三方库或无限循环动画。
- 不重构 Inspector 的 `CombatResultSummaryView`，不改攻击前火力解算、地图 tile、单位模型、marker、缩放、滚动、hit path 或手势。
- 不修改 Xcode project，不触碰或提交 `AGENT.md` 删除、`WW2Tactics.xcodeproj/project.pbxproj` 修改、`md/unity分析/` 或其他用户改动。
- 当前 `update_log.md` 含用户未提交内容时不得编辑或暂存该文件；只有开始本轮时该用户改动已被明确处理，才允许按项目规则追加 v2.16 记录。

## 当前架构依据

- `GameState.latestCombatResult` 是普通攻击后唯一结构化事实来源；其 `id` 每次结算更新，可作为一次性表现的稳定触发键。
- `CombatResultSummary` 已包含 `attackerCoordinate`、`defenderCoordinate`、`damage`、`counterDamage`、双方 HP 前后和击毁结论；View 无需也不得推断规则。
- `HexMapView.position(for:)` 是战果坐标到地图点位的既有转换；`CombatResolutionOverlay` 已禁止 hit testing，并提供组合后的 VoiceOver 摘要。
- 表现 phase 属于 `CombatResolutionOverlay` 自己拥有的短生命周期 `private @State`。用 `.task(id: summary.id)` 驱动时，新战果会取消旧任务并重新开始，不需要向共享状态写动画信息。
- CI 的 `--ci-selected-combat-result` 已通过 `handleTap(q7,r6)`、`handleSecondaryAction(q9,r6)`、`executeFocusedCommand()` 生成真实战果；新 steady-state 参数应复用这条链，只让叠层跳到最终表现 phase。
- SwiftUI 实现必须使用带 `value` 的 `.animation(..., value:)` 或明确的 `withAnimation`，异步等待使用可取消的 `Task.sleep(for:)`；禁止 `DispatchQueue`、裸 `.animation(_:)` 和不可取消延迟。

## 实现步骤

1. 在 `BattlefieldMap.swift` 内为战果叠层定义小型私有表现 phase，例如 `impact`、`damage`、`resolved`；phase 只描述绘制层级，不含伤害、坐标或规则副本。
2. 让 `CombatResolutionOverlay` 持有 `@Environment(\.accessibilityReduceMotion)` 和 `private @State` phase，并以 `.task(id: summary.id)` 驱动一次性序列。每次新 summary 先重置到命中阶段，再经过约 100-180ms 的短间隔进入战损阶段，最后在总时长约 350-500ms 内进入 resolved；任务取消后不得继续写旧 phase。
3. Reduce Motion 开启时直接进入 resolved，或只允许一次短 opacity 变化；不得出现扩张、弹跳、旋转、震动或位置移动。
4. 把现有叠层拆成职责清楚的小 View：冲击标记、HIT/RET 战损牌、中央结果标签。若拆分只服务地图反馈，可继续放在 `BattlefieldMap.swift`；不要扩大到无关文件。
5. 冲击标记锚定真实 `defenderPoint`，使用轻量 Shape stroke、短刻线和系统 symbol 表达落点；中心应保留空间，不用大面积实色爆炸覆盖敌方军械与 HP。resolved 阶段保留低对比、静态且不动画的冲击残迹，既提供命中后的视觉落点，也让延迟截图可核对。
6. HIT 牌先于中央结论出现；真实 `hasCounterAttack` 时 RET 牌在 HIT 后出现，不存在反击时不创建假 RET。`didDestroyDefender`、`hasCounterAttack` 和既有 `resultTitle/resultIcon/resultColor` 继续只读决定“击毁/交火/压制”。
7. 战损牌出现只使用轻微 opacity、约 `0.96 -> 1.0` 缩放和最多 4-6pt 位移；中央标签最后出现。禁止 spring 过冲导致文字抖动或遮住单位，禁止动画改变 overlay 的布局尺寸。
8. 所有装饰子 View 使用 `accessibilityHidden(true)`；整个 `CombatResolutionOverlay` 继续作为单一 accessibility element，沿用完整战果摘要。phase 切换不得制造三次重复 VoiceOver 元素，且结果不能仅凭红/橙颜色区分，必须保留 HIT/RET、数字、图标和文字。
9. 整个反馈层继续 `.allowsHitTesting(false)`。确认 phase、overlay 或 transition 不拦截 HexInputReader，不改变 `contentWidth/contentHeight`、`resolvedScale` 或 `position(for:)`。
10. 增加 CI 专用启动参数，例如 `--ci-selected-combat-impact-steady`：`WW2TacticsApp` 遇到它时仍只调用 v2.14 已验证的公开操作链生成真实 `latestCombatResult`；表现层检测该参数后从首帧直接进入 resolved。保留旧 `--ci-selected-combat-result`、attack preview 和 approach preview 参数。
11. steady-state 不能有专用假视图、固定文案或固定数值。它与正常 resolved 使用完全相同的 `CombatResolutionOverlay`、`CombatDamagePlate`、真实 summary 和真实坐标，唯一差异是跳过计时序列。
12. workflow 将截图场景元数据更新为明确名称（建议 `selected-combat-impact-steady`），传入新参数，保留最多 4 次、间隔 6 秒的有界重试、500 KB 门禁、设备/运行时/场景日志和未加密 artifact。不得降低截图阈值。
13. 同步 README、flow、flowchart、test 和 prompt README；`update_log.md` 按上述用户改动保护规则处理，不能为满足文档清单而混入或覆盖用户内容。

## 建议表现节奏

- `impact`：防守格周围出现约 56-66pt 的细冲击环/四向短刻线，轴线在落点处短促增强；不覆盖单位中心。
- `damage`：冲击环收敛为低对比残迹，HIT 牌出现；有反击时 RET 牌紧随其后出现。
- `resolved`：中央“交火/压制/击毁”标签出现，HIT/RET 保持可读，冲击残迹降至背景层且停止动画。
- 总节奏应短于半秒，视觉重点依次是落点、数值、结论。不得同时放大所有元素，也不得持续闪烁。

## 验收标准

1. 正常代码路径中，每个新 `CombatResultSummary.id` 只触发一次 `impact -> damage -> resolved`，重复 body 刷新不会重播；新一场攻击会取消旧任务并从新战果重新开始。
2. 代码审查确认 phase 只存在于 SwiftUI 表现层，`GameState.swift`、`GameModels.swift` 和所有规则数值无变化。
3. 命中冲击锚定 `summary.defenderCoordinate` 换算的位置；HIT、RET、HP 和结论全部只读 summary，不解析 `message`，不使用当前 selected/focused 猜测旧交战坐标。
4. Reduce Motion 路径没有扩张、缩放、位移、旋转或震动，仍能完整读出同一真实战果。
5. 所有装饰不响应输入并从 VoiceOver 隐藏；整层只暴露一次完整战果摘要，且颜色不是唯一信息载体。
6. 云端截图场景明确记录 `selected-combat-impact-steady`，PNG 为真实攻击后状态，显示目标处静态冲击残迹、`HIT -21 / 64 -> 43`、`RET -7 / 64 -> 57` 和“交火”；数值必须来自本次真实 summary，不能写死。
7. PNG 至少 500 KB、非黑屏，地图、双方单位、HP、关键 HUD 和输入层没有被大面积遮挡；与 v2.15 截图相比，新增反馈层次清楚但不过度喧宾夺主。
8. 最新 `origin/main` commit、workflow run id、run attempt 与 artifact manifest 完全一致，static、smoke、build 和 screenshot 均成功。
9. 提交范围不包含 `AGENT.md`、`project.pbxproj`、Unity 分析目录或用户既有 `update_log.md` 改动。

## 风险和禁止项

- 不能把动画状态写进 `GameState`，也不能为 UI 节奏修改 `CombatResultSummary`。
- 不能用 `Timer`、`DispatchQueue.asyncAfter`、不可取消延迟或永不停止的 repeatForever；必须保证新 summary 或 View 消失时旧序列可取消。
- 不能依赖瞬时帧作为唯一 CI 证据；延迟截图必须看到稳定 resolved 结果和静态冲击残迹。
- 不能为了 CI 把生产动画延长到 6 秒以上、循环闪烁、固定为截图画面，或创建专用假战果 View。
- 不能把 `HIT -21`、`RET -7`、`64 -> 43/57`、q/r 坐标写入叠层实现；这些只可作为验收场景预期。
- 不能让冲击图形、战损牌或结果标签盖住双方军械主体、HP 条、目标准星或地图命令入口。
- 不能用大面积发光、强烈弹簧、随机粒子或高频动画破坏战棋读图；所有绘制必须确定性且轻量。
- 不能因纯 UI 改动删除、改写或放松既有规则测试、截图重试、500 KB 门禁、artifact manifest 或失败门禁。
- 不得触碰、重置、回滚、暂存或提交用户和其他 Agent 的未提交改动。
