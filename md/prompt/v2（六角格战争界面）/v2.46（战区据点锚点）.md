## 视觉参考观察

公开商店/游戏官网中的 EasyTech《荣耀的将军3》及同系列战棋画面，值得保留的规律是：

- 地图和地貌是第一工作区信号，城市、港口、桥头和交通节点用小型建筑群、旗帜/标识和轻量轮廓形成地图锚点，而不是用大面板覆盖地图。
- 据点是战区导航节点，名称贴近节点并保持短、清楚的纸质/金属军用标牌感；归属色用于识别控制权，不能成为唯一语义。
- 地图节点有远近层级：建筑主体和旗杆/标记比普通地形纹理更醒目，但仍让道路、河流、山脊和单位模型保持可见。
- 六角格网可以作为地理结构存在，战术焦点和据点归属用少量高对比边缘、旗色和局部阴影表达；不需要每个节点都变成圆角卡片。
- 这些规律只用于表现取舍。项目不引入商店图片、网络资源、第三方库或运行时网络依赖。

## 背景与当前差距

v2.43 已把地图地貌从编辑器式网格收敛为连续战场，v2.44 让 tank/artillery/infantry/recon 具备接地的军械材质，v2.45 已把 `CombatResolutionOverlay` 的结论、HIT/RET 和 HP 前后层级做完。最新 regular PNG 已证明地图、道路/河流、军械棋子、战果、HUD 和 `AL / OBJ / AX` rail 能共同工作。

当前仍有一个真实的地图层级差距：`TerrainTile` 的据点主要只通过 `ObjectiveFlagMarker`、`ObjectiveNamePlate` 和普通 `city` 地貌的建筑簇表达。截图中据点在大面积连续地貌里容易退化成小旗子/小名字，尤其当据点所在格有单位或位于地图边缘时，玩家不能一眼把它读成“需要争夺、补给或穿越的战区节点”。底缘 `OBJ` rail 虽能定位据点，但地图本体缺少相互对应的地标锚点。

本轮不是新增据点规则，也不是重做 v2.45 的战果反馈；目标是把已有据点在地图上的视觉识别提升为克制、稳定、可扫描的战区节点。

## 目标

1. 让每个已有 `tile.isObjective` 在地图上具有一致的“据点节点”识别：建筑/地标主体、归属旗帜或中立标识、短名称三者形成稳定的局部阅读顺序。
2. 在 regular 云端 screenshot 中，使据点与普通城市/森林/平原纹理有明确但克制的层级差异；地图仍然是第一视觉信号，不把据点变成覆盖地图的大卡片。
3. 让盟军、轴心和中立据点在不依赖颜色的前提下可区分：保留可读的 `AL`、`AX`、`NEU`/中立文字或等价 SF Symbol/几何语义，同时用归属色作为辅助。
4. 让据点名称与其地标主体保持局部几何关系：不被单位模型、HP/行动轨道、道路/河流连接、地图工具栏、战果 overlay 或 `AL / OBJ / AX` rail 遮住；相邻据点和地图边缘也不能互相覆盖。
5. 复用现有 `TerrainTile`、`objectiveName`、`owner`、`isObjective`、坐标和既有焦点状态，保持 `ObjectiveJumpDock` 的 `focus(coordinate:)` 与地图 tile accessibility 事实链不变。
6. 维持 EasyTech 风格的纸张/金属/野战标识语气：有限描边、局部阴影、简洁旗杆/标牌和少量建筑结构；避免厚 blur、强渐变、荧光描边和嵌套卡片墙。

## 当前架构依据

- `TerrainTile` 在 `GameModels.swift` 中提供 `coordinate`、`terrain`、可选 `objectiveName` 和可选 `owner`；`isObjective` 只是 `objectiveName != nil` 的只读派生属性。这是据点表现的唯一事实来源。
- `HexMapView` 在 `BattlefieldMap.swift` 中将同一 `TerrainTile` 传给 `HexTileView`；`HexTileView` 已在既有 VStack 中绘制 `ObjectiveFlagMarker`、单位或 `ObjectiveNamePlate`，并从 `tile.isObjective` 派生边框和 owner wash。
- `TerrainTexture` 已从 tile 的 terrain、coordinate seed 和邻接方向绘制 city building cluster、道路、河流、山体、森林等纯表现层纹理。可以在此边界内为 `tile.isObjective` 增加确定性地标层，但不得写回 tile 或规则状态。
- `BattlefieldTheme.swift` 提供 brass、ink、mutedInk、war ledger 和地图材质 token。优先复用既有 token；若确需新增颜色，只能是地图据点专用、低对比的静态表现 token，并说明原因。
- `ObjectiveFlagMarker` 和 `ObjectiveNamePlate` 都关闭 hit testing、隐藏于 VoiceOver；`HexTileView` 负责一条包含据点、单位、焦点和地图情报的 accessibility label。任何新装饰必须保持这一单一语义节点策略。
- `HexMapView` 的 tile sibling 层级和 overlay 层级当前为：普通地形 < 有单位/焦点 tile < attack axis < v2.45 combat result overlay。v2.46 不应改变这些数值；据点增强必须在 tile 内部解决。
- `ObjectiveJumpButton` 已有据点短码、owner code、坐标和 VoiceOver 定位入口；本轮地图锚点必须与该入口保持事实一致，但不得从 rail 复制另一个据点状态。

4. 重排现有旗帜和名称牌的局部位置，使旗杆/owner code、节点主体、名称牌有清晰上下或前后关系；名称牌使用 `@ScaledMetric` 或语义字体、单行、`minimumScaleFactor`/合理缩短装饰处理空间压力。不要删除名称或 owner 事实来换取漂亮截图。
5. 处理有单位据点：单位军械、HP/行动轨道和 selected halo 仍是单位的首要层级；据点锚点应在单位周边或 tile 上缘/边缘提供可见提示，不能把名字牌塞进军械主体下方造成重叠，也不能降低单位 zIndex。
6. 处理相邻/边缘据点：利用 tile 内相对布局、有限 padding、已有 tile bounds 和 `lineLimit`/`minimumScaleFactor` 让名称牌在 86x74 画布中不溢出；不得用固定屏幕坐标、负无穷 offset 或跨 tile 的不可控大面板。边缘据点不能被 `HexMapView` 内容 bounds 裁掉。
7. 使用文字与几何/SF Symbol 双重编码控制权：盟军/轴心/中立均不能只靠颜色区分；owner code 与 `tile.owner?.shortTitle`、中立 fallback 必须保持事实一致。装饰 icon 不能新增 VoiceOver 节点。
8. 维持静态 steady-state：据点增强不依赖 `latestCombatResult`、phase、计时器或随机数；同一 tile 坐标和同一 owner/name 应稳定产生同一视觉。若使用 seed，只复用 coordinate 的确定性派生，不创建状态。

## 数据/状态流

```text
Scenario / GameState.tiles
  -> TerrainTile(coordinate, terrain, objectiveName, owner)
  -> HexMapView 逐格传入 HexTileView(tile: ...)
  -> tile.isObjective / tile.objectiveName / tile.owner 只读派生
  -> Objective landmark + owner flag/code + name plate
  -> tile 内部与普通地貌、单位、焦点和既有 marker 合成
  -> HexTileView 原有 contentShape / accessibilityLabel / input chain
```

必须保持：

- View 不写入 `TerrainTile`、`GameState` 或任何 objective owner/name；不缓存据点列表，不重新计算占领/目标/奖励。
- 据点视觉不读取 `game.message`、`latestObjectiveCaptureResult`、当前 selected/focused 以外的临时推断来替代 tile 的事实；若要强调焦点，只复用 `isFocused`/既有边框优先级。
- `ObjectiveJumpDock` 继续直接读取现有 `objectiveTiles` 并调用 `game.focus(coordinate:)`；地图地标不创建新按钮，不拦截 tile 输入。
- 所有新 `Shape`、divider、shadow、旗面、建筑高光和 owner color overlay 必须是纯渲染，`.allowsHitTesting(false)`，并在父 tile 的单一 accessibility 摘要之外保持 `.accessibilityHidden(true)`。

## 视觉层级、叠层与几何要求

- 稳定阅读顺序：据点地标主体/旗杆 -> owner code 或中立标识 -> 短名称牌 -> 低对比地面环/边缘强调。地图地貌、道路/河流和单位仍可同时定位。
- 据点锚点必须比普通 city building cluster 更容易定位，但不能超过选中单位、攻击/移动 marker、战果结论和单位 HP/行动轨道的优先级。
- 归属色只做辅助；至少保留 `AL`、`AX`、`NEU` 或等价清晰文字/符号。不要使用红/蓝颜色作为唯一的敌我语义。
- 名称牌必须与其对应的地标主体保持局部锚定，不得固定在整个屏幕的顶部/底部；不能跨越相邻 tile 中心，不得遮挡相邻据点名字、道路/河流关键转折或单位模型。
- 普通据点不应全部使用大面积不透明背景。优先窄纸签、细描边、局部阴影和小型金属/旗面层；避免厚黑矩形、强 blur、巨大阴影、发光描边、全 tile 渐变和嵌套圆角卡片。
- 既有 `tile.isObjective` border owner/focus/action 优先级不得被新装饰覆盖；选中、攻击焦点、最新占领和态势 marker 应继续压过静态据点材质。
- 不改变 `HexMapView` 的 `zIndex`、scroll/zoom、content size、tile frame、contentShape 或 `CombatResolutionOverlay` 的 `zIndex(20)`。据点装饰只能在 tile 内部组合并保持 `.allowsHitTesting(false)`。
- 地图边缘的据点仍应在当前 content bounds 内可读；不要靠负 offset 把旗杆或名称牌送出 tile/地图而让裁切成为隐性布局策略。
- 对同一地图的普通 city、盟军 objective、轴心 objective、中立 objective、有单位 objective 和焦点 objective 都应有确定性且可解释的差异，不能只为 CI 中一个已知坐标写特例。

## Dynamic Type、VoiceOver、Reduce Motion

- `HexTileView` 继续只提供一条包含据点名称、owner、坐标、单位和既有 marker 的 accessibility label；不得把旗、建筑、牌、阴影拆成重复 VoiceOver 节点。
- 新的视觉装饰继续 `.accessibilityHidden(true)`；不新增 Button、gesture、focusable element 或地图命中区域。地图输入仍由原 `HexInputReader` 完成。
- 名称牌和 owner code 应使用 `@ScaledMetric` 或语义字体，并结合 `lineLimit(1)`、`minimumScaleFactor`、合理的 `dynamicTypeSize` 范围和稳定 frame；在 `xxxLarge` 源码审查下不能因字号放大而溢出、覆盖单位或丢失 owner/name 事实。
- compact 和窄宽度源码审查必须覆盖：地图边缘据点、相邻据点、带单位据点、长中文名称、`NEU` 中立标识和 rail 同时出现的情况。没有独立 compact/窄屏 artifact 时只能报告源码审查。
- 多焦点源码审查必须确认据点静态锚点不依赖单一 `focusedCoordinate`，焦点边框/定位仍由既有 state/action 控制；不得新增焦点状态。
- 据点本轮是静态表现，不应加入动画、延迟、phase、timer 或 `withAnimation`。`accessibilityReduceMotion` 下与普通 steady-state 应看到相同的据点内容；不能用动态闪烁吸引注意。
- 任何新 `Image(systemName:)` 只能作为视觉辅助并隐藏于 VoiceOver，完整事实仍在父 tile 摘要中；颜色、旗面、描边不能是唯一信息编码。

## 验收标准

1. 最新云端 regular PNG 至少 500 KB、非黑屏，且六角地图/地貌仍是第一工作区信号；据点节点不被做成大卡片墙。
2. 在当前可见场景中，普通 city 与已有 objective 有可解释的视觉层级差异；盟军、轴心、中立据点能通过文字/符号/几何与颜色组合区分，不能只看颜色。
3. 据点的地标主体、owner 标识和名称牌形成稳定局部阅读顺序；至少一个地图上的据点能一眼读作战区节点，而不是普通地形小标记。
4. 普通、带单位、焦点、地图边缘和相邻据点没有明显名称溢出、旗杆出界、牌互盖、单位/HP/行动轨道遮挡；道路/河流和 `AL / OBJ / AX` rail 仍可读。当前 regular PNG 若不覆盖全部组合，C 必须把未覆盖组合标为源码审查而不是臆测通过。
5. 据点事实只来自 `TerrainTile.objectiveName`、`owner`、`isObjective` 和既有坐标/焦点；没有新增规则状态、缓存、数据复制或硬编码场景特例。
6. `ObjectiveJumpDock`、`focus(coordinate:)`、地图 `HexInputReader`、tile frame/contentShape/zIndex、单位模型、v2.45 战果 overlay 和地图滚动缩放行为无回归；新装饰不命中、不增加 VoiceOver 节点。
7. `xxxLarge`/compact/窄宽度/多焦点/VoiceOver/Reduce Motion/4x 的源码契约明确且无明显越界风险；没有独立输出时，C 报告不得声称这些状态已由 PNG 实测。
8. Swift diff 仅限 `BattlefieldMap.swift` 据点表现区域，必要时加 `BattlefieldTheme.swift` 的据点 token；`GameState.swift`、`GameModels.swift`、`ContentView.swift`、`BattlefieldChrome.swift`、单位/测试/project/workflow/输入文件无 diff，文档与真实实现一致。

## 风险和禁止项

- 禁止把据点增强成大面积不透明面板、厚黑卡、强 blur、荧光轮廓、巨大阴影、全 tile 渐变或营销式 hero；地图必须优先。
- 禁止复制 `TerrainTile` 列表、读取 `game.message`/战报字符串猜 owner 或名称、从当前单位状态推断据点控制权，或用固定名称/坐标/截图状态写特例。
- 禁止修改 `GameState`、`GameModels`、规则、战役数据、输入、`ObjectiveJumpDock`、HUD/rail、单位模型和 v2.45 战果层来“让节点更显眼”。
- 禁止改变 tile frame、content size、scroll/zoom、position、contentShape、zIndex 或 `HexInputReader`；禁止用屏幕固定坐标、不可控负 offset、跨 tile 巨大 overlay 解决布局。
- 禁止新增 Button、gesture、focus state、动画 state、timer、网络请求、图片资源、第三方库、workflow/project 改动或测试实现改动。
- 禁止让 owner 颜色成为唯一语义；禁止删除 `objectiveName`、owner code、坐标、单位或既有 accessibility 内容以换取 regular 截图。
- 禁止使用旧 artifact、失败包或 v2.45 PNG 冒充本轮据点表现证据；不得伪造 compact、窄宽度、`xxxLarge`、多焦点、VoiceOver、Reduce Motion 或 4x 的实测结论。
