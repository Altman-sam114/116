## 背景

当前普通战场同时存在多套整格六角视觉信号。v2.25/v2.27 已把 threat/ZOC 的主语义收敛为低透明红色 wash 并删除逐格徽记，但 `HexTileView.borderColor` 与 `borderWidth` 仍分别为 `isThreatenedMoveTile`、`isEnemyControlZone` 保留红色整格边框；v2.36 已提供连续的 `SupplyLineMarker`，但 `isSupplyLine` 仍保留绿色整格弱边。因此，非攻击聚焦的 regular 战场仍会被大面积红绿六角轮廓切碎，地貌与实体单位的阅读优先级被削弱。

历史排重边界如下：

- v2.13 只在 attack focus 期间隐藏普通态边框，退出 attack focus 后普通边框会恢复；本轮处理的正是恢复后重复出现的三个低优先级状态边框，不改变 attack-focus 过滤本身。
- v2.25/v2.27 已确立 threat/ZOC 的红 wash 主语义并移除逐格徽记；本轮只删除其残留整格 stroke 分支，红 wash 的透明度、顺序和过滤必须原样保留。
- v2.28 已确立 `isAttackCoverage` 的橙色边框为唯一射程边框信号；`.orange.opacity(0.40)` 与 `1pt` 必须冻结。
- v2.36 已用 `SupplyLineMarker` 表达连续补给路径；本轮只删除重复的绿色整格边，marker、连接方向、端点、`SUP`/`CUT` 与 BFS 事实链必须原样保留。
- v2.50 只处理静态地貌 `HexEtchedBoundaryLayer`，不属于 threat/ZOC/supply 状态边框，本轮不得触碰。

本轮唯一主题是：**删除 threat、enemy control zone、supply line 三个低优先级整格边框消费者，让常态地图回到以地貌、据点和实体单位为主，同时保留各自既有且不重复的语义载体。**

## 目标

1. 删除 `HexTileView.borderColor` 中 `isThreatenedMoveTile`、`isEnemyControlZone`、`isSupplyLine` 三个低优先级整格边框分支。
2. 删除 `HexTileView.borderWidth` 中同名三个低优先级整格边框分支。
3. 保留通用 `Hexagon().stroke(borderColor, lineWidth: borderWidth)`；普通格在删除分支后自然回落到后续 `isFocused`/objective/AI 状态，或最终 `.clear`/`0.45`，不得另写替代逻辑。
4. 保持 `isAttackCoverage` 的 `.orange.opacity(0.40)` / `1pt` 为唯一射程边框，保持 route、selected、focused、objective、AI 和其他高优先级状态的原有分支、值与相对顺序。
5. 保持 threat/ZOC 红 wash 与连续 `SupplyLineMarker` 为各自的主要地图语义，让 v2.53 regular PNG 中大面积红绿整格轮廓明显减少，而控制区、威胁与补给事实仍可读。
6. 以六行分支删除完成实现，不新增 token、状态、helper、Path、marker、资源、动画或测试实现。

## 风险与禁止项

- 最大风险是误删通用 stroke 或 attack coverage 分支，导致选中、路线、射程、focused/objective/AI 等高优先级反馈丢失。实现只能删除指定六行，不能重写 computed property。
- 删除低优先级 branch 后，部分格会命中后续 focused/objective/AI 分支，这是既有优先链的自然回落，不是异常，也不得用新 guard 阻断；无后续状态时必须保持 `.clear`/`0.45`。
