## 背景

v2.34 已把攻击后的 HIT/RET 从双行黑牌收敛为单行金属铭牌，但当前 `CombatResolutionOverlay` 仍同时承载交战轴线、冲击、两块伤害牌和中央结论胶囊。下一轮需要让玩家在真实地图工作区中按稳定顺序读出“这次交战的结论、主攻击造成的 HIT、实际反击造成的 RET、双方 HP 前后变化和是否击毁/压制/无反击”，同时让军械棋子、HP/行动轨道、HUD 与底缘 `AL / OBJ / AX` rail 继续成为可定位的地图上下文。

本轮不是新增战斗规则，而是对已有战果事实的表现层分级：`CombatResultSummary` 已经记录攻击方/防守方快照、执行时双方坐标、主伤害、反击伤害、击毁双方、机动追击、夹击加成和防御姿态消耗；View 必须把这些真实字段转化为更清楚的主次阅读顺序，不得从当前选中态、焦点态或消息字符串推测上一场交战。

## 目标

1. 把战果层明确组织为稳定的阅读顺序：交战结论优先，主攻击 `HIT` 为主要数值反馈，真实存在的 `RET` 为次级反馈，HP 前后变化附着在对应反馈上。
2. 对以下真实结论形成清晰、可扫描的文字与图标双重编码：防守方击毁、攻击方被反击击毁、交火、压制、无反击。
3. 让 HIT/RET 铭牌、交战轴线、冲击残迹和结论标记沿真实 attacker/defender 坐标布局，避免覆盖双方军械模型、HP/行动轨道、HUD、`AL / OBJ / AX` rail 和地图关键地貌。
4. 保留 v2.34 既有单行铭牌的完整信息：类型、伤害、对应一方 HP 起止值；不因追求紧凑而删除反击、无反击、击毁或结论信息。
5. 保留真实 `CombatResolutionPhase` 表现节奏、`.task(id: summary.id)` 取消链、`--ci-selected-combat-impact-steady` 真实战果 steady-state，以及已有 4x/局部裁切验收所关注的单位轨道和战果叠层关系。
6. 在 regular 云端截图中让战果信息清楚但克制，继续服务可操作的六角地图，而不是把地图变成结果卡背景。

## 当前架构依据

- `GameState.latestCombatResult` 是 `@Published private(set)` 的 `CombatResultSummary?`，只在真实普通攻击结算后写入；预览、聚焦、MOVE/POS 和火力暴露不会生成虚假结果。
- `CombatResultSummary` 的唯一事实字段包括：`attacker`/`defender` 两个 `CombatantResultSnapshot`，`attackerCoordinate`、`defenderCoordinate`，`damage`、`counterDamage`，`didDestroyDefender`、`didDestroyAttacker`、`didTriggerManeuverPursuit`、`didConsumeDefenderEntrenchment` 和 `supportDamageBonusPercent`；`hasCounterAttack`、`hasFlankingSupport` 由该 summary 只读派生。
- `BattlefieldMap.swift` 以 `summary.attackerCoordinate` 和 `summary.defenderCoordinate` 调用既有 `position(for:)`，创建 `CombatResolutionOverlay`，并以 `summary.id` 作为 View identity。当前交战轴线为较低层，战果 overlay 保持在地图 tile、单位和轴线之上；整个 overlay 已由父层 `.allowsHitTesting(false)`。
- `CombatResolutionOverlay` 当前只拥有 SwiftUI 表现所需的 private `phase`，并由 `activePhase`、`showsPrimaryDamage`、`showsCounterDamage`、`showsResolution` 控制绘制。它的 `.task(id: summary.id)` 在新战果或 View 消失时取消旧序列。
- `CombatDamagePlate` 只接受调用方传入的 system image、文字、HP 文本和颜色；它不能访问 `GameState`，不能自行计算数值。所有铭牌和冲击装饰都应继续 `accessibilityHidden(true)`，父 overlay 只提供一条完整无障碍摘要。
- `@Environment(\.combatResolutionSteadyState)` 下，overlay 必须直接使用同一份真实 summary 的 resolved 画面；不能制作固定数字、假战果或专用结果 View。`@Environment(\.accessibilityReduceMotion)` 下必须直接呈现同一完整 resolved 结果，不播放缩放、位移、旋转、震动或弹簧过冲。

## 实现步骤

1. 先在当前 `origin/main` 上检查现有 overlay 的所有数据入口和 phase 约束，确认实现仍只接收 `CombatResultSummary`、两个执行时坐标和既有环境值。
2. 将结果结论改为从 summary 纯派生的明确优先级：防守方被击毁显示“击毁”；防守方未被击毁但攻击方被反击击毁时显示“反击击毁”或等价明确文本；存在真实反击时显示“交火”；无反击且未击毁时显示“压制”，并显式补充“无反击”。不要从 `game.message` 或当前单位是否仍存在来推断这些状态。
3. 保留主攻击铭牌的 `HIT`、`summary.damage`、`summary.defender.startingHP -> summary.defender.endingHP`，保留真实反击时的 `RET`、`summary.counterDamage`、`summary.attacker.startingHP -> summary.attacker.endingHP`。主攻击和反击使用不同 SF Symbol、文字前缀和可读方向；颜色只能辅助，不能成为唯一编码。
4. 重排 overlay 的局部几何：使用 `attackerPoint`、`defenderPoint`、既有 trimmed axis 和局部轴向/法向计算，把 HIT 贴近防守方、RET 贴近攻击方，结论放在两者之间的独立阅读位。短交战距离、斜向交战和相邻单位必须使用确定性适配间距，不能让两块牌互相覆盖，也不能使用固定屏幕坐标或遮挡 unit piece、HP/行动轨道。
5. 建立清楚的层叠关系：单位/地貌与交战轴线保持地图结构优先；结论是战果文本的一级焦点，HIT 是主要数字牌，RET 仅在真实存在时作为次级数字牌，冲击残迹和描边是低对比装饰。结论、铭牌、冲击点不得盖住右上 HUD、底缘 rail 或地图操作层；所有新装饰继续不命中。
6. 视觉上保持 EasyTech 风格的克制军报感：使用既有深色/金属/战场色 token 和 SF Symbols，减少厚黑卡、强 blur、巨大阴影、荧光边框和大面积渐变。铭牌仍应单行、可读、具备 `@ScaledMetric`/语义 Dynamic Type 响应，并在空间不足时优先缩短装饰而不是删除事实。
7. 不新增结果动画状态。沿用现有 `phase`：正常路径继续 `impact -> damage -> counterDamage（若有）-> resolved -> dismissing -> hidden`；steady-state 和 Reduce Motion 继续直接显示完整 resolved。若需要动画，仅复用现有 phase 驱动的 opacity/轻微出现效果，不改变计时、位移边界或 VoiceOver 生命周期。
8. 更新同步文档，明确 v2.45 只改变战果叠层的阅读层级和几何，不改变规则事实、坐标、输入、phase、steady-state 或无障碍契约。

## 战果数据流与状态流

```text
玩家执行既有 ATK
  -> GameState.attack(attackerID:targetID:)
  -> 真实 HP / 反击 / 击毁 / 追击 / 姿态 / 经验规则结算
  -> GameState.latestCombatResult = CombatResultSummary
       （含双方 snapshot、执行时双方 coordinate、damage/counterDamage、结论 flags）
  -> BattlefieldMap 读取 latestCombatResult
  -> position(for: summary.attackerCoordinate/defenderCoordinate)
  -> CombatResolutionOverlay(summary, attackerPoint, defenderPoint)
  -> phase 仅控制 impact/HIT/RET/resolved/dismissed 的表现生命周期
  -> 视觉层从同一 summary 只读绘制结论、HIT、RET 和 HP 前后
```

必须保持以下边界：

- View 不写 `latestCombatResult`，不保存第二份 summary，不从 selected/focused/current unit 反推坐标或数值。
- View 不重算伤害、反击、击毁、无反击、压制、追击、夹击或姿态结果；若需要显示它们，只读取 summary 已有字段。
- `phase` 仍是唯一表现生命周期来源；不得用新的 `@State`、计时器或 dispatch 任务替代 phase，也不得把 phase 写入 GameState 或模型。
- 新的普通攻击会由 `.task(id: summary.id)` 取消旧表现；旧结果不能继承 hidden、旧结论或旧坐标。

## 视觉层级与层叠要求

- 阅读顺序必须稳定为：`结论` → `HIT` 主攻击与防守方 HP 前后 → `RET` 次级反击与攻击方 HP 前后（若存在）→ 低对比冲击/轴线。无反击时不能只靠“没有 RET 牌”表达，必须在结论或次级 qualifier 中出现“无反击”文字/图标。
- 防守方击毁、攻击方被反击击毁、交火、压制和无反击都必须同时有文字和图标编码；不能只换颜色、透明度或边框。
- HIT 与 RET 必须在交战轴两端有明显方向关系，保持可读间距；不能重叠、互相覆盖、穿过单位主体或压住底部 HP/移动/开火轨道。
- 结论位不得与任一铭牌共享相同矩形空间；短距离或斜向交战要通过局部轴向/法向适配、缩短 padding/字号或降低装饰来解决，而不是把三者叠成黑牌墙。
- `CombatResolutionOverlay` 继续高于地图 tile/单位/axis，但其内容必须透明地避开 `MapActionHUD`、通讯坞、`AL / OBJ / AX` rail 和地图工具栏；不能改变已有 `zIndex` 数值来掩盖布局问题。
- 战果层不得改变 `contentWidth`、`contentHeight`、tile frame、scroll/zoom 或输入 hit shape；overlay、轴线、冲击点和铭牌均保持 `.allowsHitTesting(false)`。
- 结论可以是战果文字的最强视觉锚点，但整体对比度、阴影和尺寸必须低于会遮住军械模型的“大卡片”阈值；地图和单位仍是场景第一视觉信号。

## 无障碍、Dynamic Type 与 Reduce Motion 要求

- 父 `CombatResolutionOverlay` 继续 `.accessibilityElement(children: .ignore)`，提供一条完整摘要，至少包含结论、攻击方/防守方名称、HIT 伤害和 HP 前后、真实 RET 或“没有反击”，必要时包含攻击方被反击击毁的信息。
- HIT/RET 图标、结论图标、分隔线、冲击环、轴线、阴影和所有新装饰继续 `.accessibilityHidden(true)`，不得制造重复 VoiceOver 节点。
- hidden phase 继续不暴露 overlay；resolved、steady-state 和 Reduce Motion 继续暴露同一份真实完整摘要。不得用视觉隐藏替代无障碍隐藏。
- 铭牌文字使用 `@ScaledMetric` 或语义字体，保持单行与 HP 数字的可读性；在 `xxxLarge`/窄宽度源码审查中不得越界、截断成无意义片段或因为字号放大遮挡地图。
- `accessibilityReduceMotion` 为 true 时不得播放 scale、offset、rotation、spring、shake 或延迟逐项出现；必须直接显示与正常 resolved 完全相同的信息和结论。steady-state 同样直接显示完整 resolved，不能使用专用假文案。
- 不新增 VoiceOver、Reduce Motion 或 Dynamic Type 专用规则状态，也不把 regular PNG 冒充 compact/窄屏/大字号/多焦点实测证据。
