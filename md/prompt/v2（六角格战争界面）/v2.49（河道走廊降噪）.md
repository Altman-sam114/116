## 背景与单一主题

v2.48 已完成平原、森林、城市、山地、雪地的局部材质节奏收敛。对该轮 final regular PNG 的实际审阅显示，河流仍由宽蓝色 connection stroke、圆端节点和局部中心水池共同形成高饱和的重复圆节；在贯穿地图的长河上，这些圆节比道路和部分军械/据点更抢视线，河道容易读成透明管线而不是战场地理边界。

本轮唯一主题是：**将既有 river connection 收敛为克制、连续的河道走廊**。只调整 river 的静态纯绘制层级、窄度和局部高光，使水道作为可追踪的地理走廊留在单位、据点、marker、战果、HUD 与 `AL / OBJ / AX` rail 之下。

这不是道路环路、白昼明度或五类非河流地貌材质纹理的重复轮次。EasyTech 参考只用于取舍，不引入图片、网络或资产管线。

## 目标

1. 在 `selected-combat-impact-steady` regular screenshot 中，让连接河流读为连续、窄而有浅深层次的走廊，不再由逐格大蓝圆节主导。
2. 保持既有 `connectionDirections`、`connectionPath`、river tile 坐标和地形事实不变；只重排同一 path 的 river bank/shadow、主水槽和细高光的静态表现权重。
3. 移除或显著收敛会放大 tile 中心圆节的 river-only 中心水池装饰；孤立 river tile 仍须通过小型、克制的局部水面形态清楚可辨，但不得重建连接网络或借大圆补偿。
4. 建立明确层级：土地/五类地貌底材 < 河岸与主水槽 < 道路和据点主体 < 单位/owner/HP/行动轨道 < selected/action/威胁/路线 marker < HIT/RET/战果/HUD/rail。
5. 所有结果必须只由既有 `TerrainTile.terrain`、tile bounds 和 `connectionDirections` 确定性派生；不新增状态、缓存、timer、动画、随机源、图片、网络、第三方依赖或无障碍节点。

- `BattlefieldTheme.swift` 是静态表现 token 的唯一位置。本轮可新增只供 river 走廊消费的低饱和 river bank/main channel/highlight token；每个 token 都必须被 `TerrainTexture` 使用，不能改动 War Ledger、单位、阵营、marker、v2.47 白昼或 v2.48 五类地貌 token。

## 实现步骤

1. 在 `847f4a7` 基线上核对 `TerrainTexture` 的 river 路径实际组成：connection shadow、`TerrainKind` 提供的既有主 stroke、river highlight 与 `waterHighlight` 中心形态；明确哪个 river-only 层造成圆节。
2. 在 `BattlefieldTheme` 定义少量 river-only token，分别对应弱河岸/接地、低饱和主水槽和极细流向高光。不要复用或修改道路、白昼、owner、warning 或五类地貌 token。
3. 在 `TerrainTexture.connectionLayer` 为 `.river` 使用同一既有 `Path` 的专属三层静态 stroke；宽度应显著小于当前视觉圆节，并使用 round join/cap 维持 tile 边缘连接，但不得增加新的 path、端点或跨 tile overlay。非 river 分支必须保持 byte-for-byte 逻辑等价，尤其道路。
4. 将 `waterHighlight(in:)` 收敛为低权重的 river-only 局部补充，或在有连接时不再绘制中心 pool；若无连接，使用 tile 内小型细长水面/短流线保持识别，不能回到大圆或形成每格波纹模板。
5. 以现实截图检查连续长河、河流与道路邻近、河畔单位/据点、选中态、MOVE/ATK/POS/THR/SUP marker、HIT/RET 和底缘 rail。河流可追踪但不得遮挡这些高优先级信息；不要通过提高它们的 zIndex 或改变布局来补救。
6. 检查确定性、几何和访问性：所有 river 装饰限制在既有 tile bounds/`Hexagon` clip，关闭命中并隐藏于 accessibility；不读取 message、phase、selected、focused、时间或随机数改变水面。
7. 同步 README、flow、flowchart、test、update_log、prompt README，准确写明本轮仅收敛 river 走廊表现；实现前不得预填未知 commit/run/artifact/digest，push 后由 B 和 C 写入真实事实。

## 数据与表现流

```text
TerrainTile(.river, coordinate) + existing connectionDirections
  -> unchanged connectionPath / endpoint geometry
  -> TerrainTexture river-only bank + main channel + fine highlight tokens
  -> tile-local clipped, static river corridor
  -> existing supply/route/marker/objective/unit/combat/HUD/AL-OBJ-AX layers
  -> existing contentShape, input, scroll/zoom and one tile VoiceOver summary
```

不得写回 `TerrainTile`、`GameState` 或模型；不得新增 `@State`、`@Published`、environment state、cache 或 runtime resource。river 只消费既有 tile 与方向输入，五类非河流材质、道路和所有规则状态继续走原流。

## 视觉层级与几何约束

- 河岸应低对比、主水槽比现有 11pt 视觉带更窄，高光仅作细线提示；避免每个 junction 出现显眼的同径蓝色圆盘。
- 连接必须在相邻 river hex 边缘连续，不能露出白缝、断头、额外桥接或跨越非 river 地格。
- 不改 `connectionPath`、`endpoint`、`connectionDirections`、`TerrainKind.showsMapConnections`、道路的 color/width/highlight 或 canonical road network。
- 不改 `HexTileView` 绘制顺序、tile 几何或 sibling 层级；不得用负 offset、屏幕固定坐标、global overlay 或新增绘制网络取得连续感。
- regular 截图中的地图仍是第一工作区；单位/据点/marker/战果/HUD/`AL / OBJ / AX` rail 必须在河流之上清楚可读。
