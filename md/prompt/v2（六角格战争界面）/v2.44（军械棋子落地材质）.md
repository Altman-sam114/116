## 背景与问题

`BattlefieldUnitViews.swift` 已由既有 `UnitKind`、`Faction` 与 spent 状态派生五层 `UnitModelView`，`MapUnitPiece` 也已有阵营椭圆环、HP、军衔、CUT/战术状态和将领牌。但棋子目前仍偏若干叠加几何路径：地面环、模型内 blur shadow、厚度和装备面彼此没有统一的“底座—接地—军械主体”材质语言；坦克、炮兵、步兵、侦察虽能辨认，第一眼的重量、落地感和阵营漆面层级仍不够稳定。状态小标签也不应和军械主体抢同一视觉层。

本轮目标是借鉴“地图优先、兵种可一眼辨认、棋子有接地重量”的通用战棋体验原则，创作原创 SwiftUI 形状与渐变：让四种单位成为克制、可读、落在六角地貌上的微缩军械棋子。不得复制 EasyTech、将军的荣耀、世界征服者或任何第三方的截图、排版、色值、模型、肖像、军徽或素材。

当前 CI 只生成 `selected-combat-impact-steady` 的 regular battlefield PNG。因此 regular PNG 是本轮地图单位视觉的主要证据；compact、窄屏、`.xxxLarge` 及以上 Dynamic Type、不同焦点、VoiceOver 和 Reduce Motion 只能由源码审查，不能由 regular 截图冒充为实测。

## 目标

1. 为地图 `MapUnitPiece` 建立一个原创、静态、低噪的三层实体关系：最下方为克制的接地接触阴影，中层为可辨认但不厚重的阵营底座/细 rim，上层为军械主体。底座应服从单位的现有 `width`/`height`，不碰 tile frame、地图坐标或命中区域；不得重叠成多个竞争的圆环、虚线或高亮圈。
2. 让 `UnitModelView` 的材质统一为“暗色厚度 → 阵营主体漆面 → 军种装备面/结构线 → 少量顶缘高光”的固定层级。阵营辨识应由现有 `Faction` 事实派生，既有 allies/axis 的清晰区分保持，但避免荧光、过饱和或另起一套状态颜色。
3. 保持四种 `UnitKind` 的原创、无文字轮廓在 regular 尺寸下可区分：
   - `tank`：低而宽的履带/车体、炮塔和炮管，读作装甲重量；
   - `artillery`：炮轮、炮架/炮盾与斜向炮管，读作牵引火炮；
   - `infantry`：三人队形、钢盔/躯干与步枪方向，读作步兵班；
   - `recon`：较轻的车体、轮组和天线/观察轮廓，读作侦察车。
   可以重构私有 `Shape` 路径和 overlay 顺序，但不可添加文字兵种码、图片、真实军徽、肖像或第三方图形。
4. 让模型材质在地图上优先于低频地貌、低于 selected/reticle/marker/交战反馈：正常棋子有清晰阴影与上缘高光，`isSpent` 继续仅由既有 `hasMoved && hasAttacked` 派生并整体降权，不能变成新状态或被隐藏。`selected` 的暖金地环、棋子上抬和阴影仍由既有 `HexTileView`/`SelectedUnitGroundHalo` 负责，不能在单位 View 内复制第二套 selected 效果。
5. 对已有可见状态做“主体优先”的降权而非删改：保留军衔、HP/readiness、CUT、`UnitTacticalStatus`、将领牌的原有事实、文本、出现条件、无障碍摘要与语义；它们可以只在同一原位置以内调整为更克制的材质/透明度/描边，使其不压过军械轮廓，但不可新增状态胶囊、重排信息、改颜色含义或删除任何提示。
6. 保持地图单位与非地图 `UnitShapeBadge` 的共有军械语言：可为 `UnitModelView` 增加仅限表现的 presentation 参数或私有 helper，让 `MapUnitPiece` 获得地图实体层级，紧凑 badge 保持其现有尺寸、标签与 action 语义；不得迫使 `ContentView` 或 `BattlefieldChrome` 改调用方。若共享改造会伤害紧凑 badge 可读性，应保守保留其既有紧凑表现，只更新地图路径。
7. 维持真实操作、结构和无障碍：`UnitCounter` 继续以当前完整 `BattleUnit` + `GameState.supplyState(for:)` 只读派生内容，并保持现有组合 VoiceOver 摘要。HP、M/A/ready 资源、将领、selected、spent、zIndex、tile `contentShape(Hexagon())`、tile frame/position/id、地图 marker、HIT/RET、战果 phase、所有点击/主次 action 和 `HexInputReader` 均不得改变。

## 当前架构依据

- `HexMapView` 只读 `GameState` 的 tiles、单位、选择/焦点、路线、补给与 marker；`HexTileView` 的单位层以 `UnitCounter(unit:)` 组合。含单位 tile 的 sibling `zIndex` 已由地图层派生，交战轴线位于 tile 上方、`CombatResolutionOverlay` 位于更高层。单位材质必须完全服从这一现有排序。
- `UnitCounter` 读取 `BattleUnit`、`GameState.supplyState(for:)`、HP ratio、rank、commander、tactical status 和 `hasMoved/hasAttacked`，其 `accessibilitySummary` 是地图棋子的唯一完整摘要。`MapUnitPiece` 负责模型、阵营地环、军衔、CUT/战术 visual；`MiniHealthBar` 与 ready pip 仅读现有状态。这一事实链不可变。
- `MapUnitPiece` 当前用 `kind.mapPieceWidth` 和固定 44pt 高度渲染；`HexTileView` 对 selected 只额外放置 `SelectedUnitGroundHalo()`，并将 `UnitCounter` 上移 3pt。新接地材质必须在这既有画布内工作，不可增大 tile、修改 hit test 或再造 selected ring。
- `UnitModelView` 同时被地图 `MapUnitPiece` 与非地图 `UnitShapeBadge` 使用。`UnitMarkerShape`、`UnitModelPlateShape`、`UnitModelDetailShape`、`UnitModelHighlightShape` 是已有的纯几何表达；可在本文件内重构为更清楚的原创轮廓，但输入仍只有 `kind`、`faction` 和 `isSpent`。若需要区分地图/紧凑场景，只能使用纯表现参数，不能写入 `GameState`。
- `BattlefieldTheme` 是跨表现层颜色 token 的唯一位置；v2.42 War Ledger 和 v2.43 map ground token 已锁定。单位专用 token 必须有明确命名，不能把匿名 opacity 散落到多个调用方或影响战区账本/地貌。

2. **地图军械可读性**：regular PNG 中 tank/artillery/infantry/recon 四类地图棋子无文字也可互相区分；接地阴影、阵营底座、主体漆面、装备细节与有限高光读为同一实体，不出现厚黑卡片、双重 ring、强 blur、荧光、高频纹理或覆盖地貌的巨大阴影。
3. **层级不回归**：军械主体高于 v2.43 低频地貌，低于 existing selected halo/reticle/marker/交战反馈；selected 的暖金实体焦点仍单一明确；HP/ready、rank、将领、CUT/战术状态保留其事实与可读性，spent 仍只由已移动且已攻击派生。
4. **规则、输入与战果不回归**：`UnitKind`/`Faction`/`BattleUnit` 数据、supply/HP/行动、`UnitCounter` 组合 VoiceOver、tile frame/position/id/`contentShape`、zIndex、`HexInputReader`、所有 action、scroll/zoom/focus、marker、HIT/RET、战果 overlay/phase 和 Reduce Motion 均保持。不得因视觉改造改写或重复规则。
5. **响应式和无障碍边界**：所有新增装饰 `allowsHitTesting(false)` 且 `accessibilityHidden(true)`；单位完整摘要、现有 action 和 44pt 相关契约保持。compact、窄屏、`.xxxLarge`、多焦点、VoiceOver、Reduce Motion 在报告中明确仅有源码审查证据。
6. **范围与文档闭环**：源码仅在允许的 UnitViews/必要 Map unit composition/Theme；GameState、GameModels、地图数据/规则/路线/input、ContentView、Chrome、project、workflow、测试实现、战果 overlay 均无 diff。README、flow、flowchart、test、prompt README 和 update_log 与真实实现及精确云端事实一致。

## 风险与禁止项

- 最大视觉风险是把局部军械纹理画成复杂小图标，使低分辨率下反而不可辨，或用过大的底座/阴影遮住单位邻格与 selected/marker。优先级应是“地貌 < 接地 < 军械实体 < 现有状态文字 < selected/marker/战果”，并在 regular 截图实际审查。
- `UnitModelView` 同时服务地图与紧凑 badge。不得仅为地图效果破坏侧栏、HUD、rail 或部署卡的 badge 尺寸/标签/无障碍；优先使用纯表现参数或保守的 geometry-relative shared shapes。
- 不得新增 `@State`、计时器、随机数、异步加载、持续动画、缓存事实、ViewModel 或对 `GameState` 回写。模型外观只能由已有 inputs 确定性重绘；Reduce Motion 不可被新动画破坏。
- 禁止把 status 降权理解为删除/合并数据，禁止改 `CUT`、战术状态、HP、ready、rank、commander、selected、spent、HIT/RET 的真实条件或 VoiceOver。禁止移动或覆盖 `CombatResolutionOverlay`；相关反馈层级留待 v2.45。
- 禁止本地 Swift/Xcode/模拟器/RulesSmokeTest/XCTest/截图；禁止提交或 push 非本轮文件；C 未完成 `gh auth login`、精确 artifact 下载、manifest/SHA/run/attempt 核对与 PNG 实看前，任何人不得宣称 v2.44 通过。
