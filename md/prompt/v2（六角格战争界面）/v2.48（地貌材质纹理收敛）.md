## 背景与当前差距

v2.47 已把地图从偏暗状态拉回可读的白昼暖纸张层级，但最新 regular 截图仍显示普通地图容易读成“每格独立的六角贴片”：平原色块、森林树符号、城市道路纹理、山体切面和雪地曲线在相邻格内以相似节奏重复，局部纹理的视觉权重接近地貌本身，连续战区因此仍有棋盘编辑器感。这个问题属于 `TerrainTexture` 的材质表达，不需要改变地图几何或规则。

v2.43 已处理低频底材、弱接缝和森林/山体的邻接连续阴影；v2.47 已处理整体明度阶梯。因此 v2.48 只处理“每种地貌如何以少量确定性材质形态形成区域感”，不重新处理六角边界、道路环路或白昼曝光。

EasyTech 风格的可执行方向是：底材安静，地貌用有限的色块、接地面和结构线表达，邻近格共享视觉语汇但不形成重复图案墙；军械、据点、战果与操作标记仍是最高可读层。所有参考只用于表现层取舍，不引入商店图片、运行时网络资源或新的资产管线。

## 单一主题

本轮唯一主题是：**收敛地貌局部纹理，建立连续战区材质语汇**。

范围只包含平原、森林、城市、山地、雪地的静态局部纹理密度、形态和对比层级。道路和河流连接路径不属于本轮主题，必须保持现状。

## 目标

1. 在 `selected-combat-impact-steady` regular screenshot 中，让普通地图从重复的逐格纹理读成连续的野战地表；白昼底材、地貌色相和六角格位置保持不变。
2. 为每类非道路/非河流地貌建立克制且可辨的材质层级：平原使用少量低对比地块，森林使用成簇树冠与接地阴影，城市使用稀疏建筑/街廓结构，山地使用有限山脊面与脚部阴影，雪地使用少量漂移曲线和针叶树细节。
3. 使用既有 `terrainSeed`、q/r 坐标和 `connectionDirections` 做确定性局部变体；同一坐标在 steady-state 下始终相同，不读取时间、战斗 phase、消息或随机源。
4. 让相邻同类地貌的视觉语汇相互呼应：森林/山地可继续复用 v2.43 已有邻接 continuity path，但不得新建地图连接网络、改变路径方向或扩大到道路/河流规则连接。
5. 降低局部纹理对地图的编辑器噪声：不让每格都出现同样数量、同样位置、同样强度的符号；保留少量“主形态 + 支撑纹理”，让单位、据点、marker、战果、HUD 和 `AL / OBJ / AX` rail 在普通地貌上拥有清晰前景对比。
6. 以静态纯表现完成，不新增状态、缓存、timer、动画、用户设置、图片、网络请求或第三方依赖。

## 实现步骤

1. 从当前 `dea1cae` 检查 `TerrainTexture` 五类局部纹理的实际重复来源：每格元素数量、坐标分布、阴影/高光、边缘裁切和与 v2.43 continuity path 的关系；记录每类最小改动点。
2. 建立一组只供局部纹理使用的静态 token。先统一材质语汇和对比度，再调整元素数量/形态；不得从 `mapParchment*` 或 `TerrainKind.mapColor` 继续推导新的亮度主题。
3. 将每类纹理收敛为“一个主形态 + 少量支撑形态”的确定性变体：允许通过 `terrainSeed` 选择稀疏/标准/簇状节奏，但不要每格都完整复制同一组图案；不要引入随机、状态或缓存。
4. 平原保留低对比地块而非贯穿线；森林保留树冠可辨性但减少等间距树符号和黑色重复阴影；城市保留道路/建筑方向感但降低小建筑网格密度；山地保留两面体量和雪顶但减少重复尖峰；雪地保留漂移与针叶树但让空白雪面成为主材质。
5. 严格不改道路/河流：`connectionPath`、`RoadConnectionNetwork`、`connectionDirections`、connection width/color/highlight 和规则/输入都不得进入本轮重构；如共享 helper 造成 diff，复制/抽取必须先停止并报告。
6. 检查相邻 tile 的视觉节奏：同类地貌应有低频呼应，不同类地貌应保留色相/结构边界；不得靠增加接缝、修改 tile frame 或新增跨 tile overlay 达成效果。
7. 检查高优先级内容：据点建筑/旗杆/名称牌、tank/artillery/infantry/recon、HP/行动轨道、selected/spent、路线/威胁 marker、HIT/RET/交战结论、HUD 和 `AL / OBJ / AX` rail 必须继续清晰，且不改变其布局、层级、命中或无障碍语义。
8. 检查确定性和访问性：同一 q/r 与 terrain 在 steady-state 使用同一纹理；所有装饰关闭 hit testing、隐藏于 accessibility；不新增文字、按钮、动画或 Reduce Motion 分支。
9. 更新 README、flow、flowchart、test、update_log 和 prompt README，如实说明本轮只收敛地貌局部纹理，不改变规则、地图几何、道路/河流、输入和既有反馈。实现提交前不得预填未知 commit/run/artifact/digest。

## 数据与表现流

```text
TerrainTile(terrain, coordinate) + existing connectionDirections
  -> TerrainTexture 的 terrainSeed / 局部确定性变体
  -> BattlefieldTheme 地貌材质 token
  -> 既有 tile 内纯绘制纹理
  -> 道路/河流、marker、据点、单位、战果、HUD、AL/OBJ/AX 保持既有叠层
  -> 原有 tile frame/contentShape/input/accessibility 链
```

必须保持：

- 不写入 `TerrainTile`、`GameState` 或任何规则状态，不复制 terrain 数据，不缓存纹理，不新增 `@State`/`@Published`/环境状态。
- 不读取 `game.message`、combat result、phase、timer、selected/focused 以外的临时信息来改变静态材质；最好不读取任何 UI 状态。
- 不改变 `TerrainTexture` 之外的 tile 位置、frame、zIndex、命中、滚动、缩放、focus 或动作链。
- `HexTileView` 继续只提供一个包含地形、据点、owner、坐标、单位和既有 marker 的完整 VoiceOver 摘要；纹理装饰不产生重复语义。

## 视觉层级与几何要求

- 视觉优先级保持：白昼底材 < 地貌主形态 < 道路/河流与据点主体 < 单位/owner/HP/行动轨道 < selected/action/威胁/路线 marker < HIT/RET/战果结论/HUD/rail。
- 局部纹理必须被限制在既有 tile bounds 和 `Hexagon` clip 内；不得使用负无穷 offset、屏幕固定坐标、跨 tile 新 overlay 或新几何网络。
- 不改变 `HexMapView` 的 tile sibling 层级和 `CombatResolutionOverlay` 层级；不靠提高纹理 zIndex 或遮挡高优先级层解决可读性。
- 保留 v2.43 的已有 forest/mountain continuity path 语义；本轮只调其与局部纹理的视觉平衡，不重新定义连接方向或绘制网络。
- 纹理应以低频块面、接地阴影和少量结构线为主；禁止密集图标墙、等距重复图案、强对比黑边、全 tile 发光、厚 blur、强渐变和大面积 wash。
