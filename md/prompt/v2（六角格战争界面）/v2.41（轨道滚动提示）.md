## 背景与问题

v2.38 已将地图底缘收敛为单一深色半透明 `AL / OBJ / AX` 支援轨道，v2.39 已处理 compact 和大 Dynamic Type 下的短可视标签、稳定项目高度和完整 VoiceOver 语义。当前 `BattlefieldChrome.swift` 的 `ObjectiveJumpStrip` 仍有三个独立横向 `ScrollView`，但 `showsIndicators` 为 `false`，项目内容溢出时没有明确的边缘渐隐、方向箭头或轻量“还有内容”提示。用户可能只看到首批单位/据点而不知道可以横向滚动；焦点跳到轨道外的项目时，也没有可靠的轨道内可见性反馈。

当前 regular workflow 只生成 `selected-combat-impact-steady` regular PNG；compact、超大 Dynamic Type 和不同焦点状态没有专用截图。因此本轮必须把响应式行为写成可审查的本地 SwiftUI 表现契约，同时不把 regular PNG 冒充 compact/Dynamic Type 证据。

## 目标

1. 当某一段 `AL`、`OBJ` 或 `AX` 的完整内容超过该段可视宽度时，显示低对比、方向正确且不会遮挡项目文本的可见滚动提示：边缘渐隐 + 轻量方向提示/状态提示；内容未溢出时不显示假提示。
2. 根据每段横向滚动位置更新 leading/trailing 提示：位于起点时明确还有后续内容，已经向后滚动时保留返回方向提示，到达末端时隐藏不再需要的方向提示。提示不得依赖系统默认滚动条才能成立。
3. 当既有 `game.focusedCoordinate` 或 `game.focusedUnit` 改变时，只在对应的 `AL`、`OBJ` 或 `AX` 段内用 `ScrollViewReader` 将当前项目滚入可见区域，优先使用稳定 item id 和中间/最近锚点；不改变既有地图 `ScrollViewReader` 的焦点滚动链。
4. 在 compact、窄宽度和 `dynamicTypeSize >= .xxxLarge` 下，保持六角地图优先和现有底缘轨道高度预算。继续使用 v2.39 的兵种 code/`OBJ` 短可视标签与视觉字号上限，不能让提示行把轨道撑成第二个信息面板，也不能挤压或缩小地图工作区到不可玩。
5. 保持每个轨道 item 至少 44pt 的可点区域、既有 72/84pt 项目宽度和 48/50pt 项目高度契约；焦点边框、阵营色底线、HP、M/A、归属、坐标和透明 item 视觉保持清楚。
6. 保持 VoiceOver 完整语义：section 仍读出 AL/OBJ/AX 的含义和数量，单位/据点仍读出完整名称、阵营/归属、HP、行动、将领、补给和战术状态；滚动提示只能补充“还有项目/向左或向右滑动”，不得以短可视 code 替代无障碍全文。
7. 所有提示和焦点滚动都是 SwiftUI 本地表现状态；Reduce Motion 时取消自动滚动动画和提示动画，不改变焦点目标、按钮 action 或任何 `GameState` 事实。

## 当前架构依据

- `BattlefieldView` 在 `BattlefieldChrome.swift` 中组合 `MapCommandCenter` 与默认收起的 `BattlefieldSupportDeck`。`MapCommandCenter` 的地图 `ScrollViewReader` 负责 `focusedCoordinate` 的地图定位，底缘 `ObjectiveJumpDock` 是地图 `ZStack` 内的覆盖表现，不进入规则层。
- `ObjectiveJumpDock` 当前只包装 `ObjectiveJumpStrip`、`MapHudBackground` 和约 66pt 的底部轨道高度；不得通过增加永久纵向面板破坏地图优先构图。
- `ObjectiveJumpStrip` 当前从 `game.mapFriendlyFocusUnits`、`game.objectiveTiles.sorted(by: objectiveSort)`、`game.mapEnemyFocusUnits` 读取三组完整数组，按 compact/regular 比例构造 `ObjectiveJumpSection`。每个 section 内有独立的横向 `ScrollView`/`LazyHStack`。
- `ObjectiveJumpSection` 当前显示短码/数量标题和项目内容；`ObjectiveJumpButton`、`UnitFocusButton` 保持透明 item、焦点描边和阵营色底线，分别调用既有 `GameState` 定位/选择入口。`ObjectiveJumpButton` 的焦点依据是 `game.focusedCoordinate == tile.coordinate`；`UnitFocusButton` 的焦点依据是 `game.focusedUnit?.id == unit.id`。
- v2.39 当前约定：compact item 宽度 72pt，regular item 宽度 84pt；普通字号 item 高度 50pt，大字号短布局高度 48pt；`usesLargeTypeLayout` 在 `.xxxLarge` 及以上成立，短布局视觉 Dynamic Type 封顶 `.large`，完整 accessibility 文案不封顶。
- 允许在 `BattlefieldChrome.swift` 内把 `ObjectiveJumpSection` 拆成少量可复用的私有表现 helper，并使用本地 `@State`、`GeometryReader`/`PreferenceKey`、`ScrollViewReader` 和已有 `BattlefieldTheme` token 追踪内容宽度、viewport、滚动偏移和 cue 可见性。不要把这些状态提升到 `GameState`。
- 若需要新增 token，只能在 `BattlefieldTheme.swift` 增加表现层颜色/透明度常量；优先复用 `commandDeckDeep`、`fieldGlass`、`hairline`、`brass`、`mutedInk`。提示/渐隐层必须 `.allowsHitTesting(false)`，实际 item Button 仍可正常横向滚动和点击。

## 实现步骤

1. **同步并确认边界**：先执行以下命令，确认本轮从最新 `origin/main` 开始；若出现非本轮改动，不得 reset、checkout 覆盖或删除。

   ```sh
   git fetch origin
   git switch main
   git pull --ff-only origin main
   git status --short --branch
   ```

   再阅读本 prompt、v2.40 prompt、全部必读文档及指定表现层源码，确认当前 `ObjectiveJumpStrip` 未被后续提交改写。

2. **保留三段事实链**：不改三组数组来源、排序和比例；只为每个 `ObjectiveJumpSection` 增加稳定的 section-local scroll metrics。内容宽度、viewport 宽度和滚动偏移应使用 iOS 17 可用的 SwiftUI 机制确定性派生，并用小 epsilon 防止浮点抖动导致 cue 反复切换。无溢出时 `canScrollLeading`/`canScrollTrailing` 必须都为 false。

3. **实现边缘渐隐**：在每个独立横向轨道的 leading/trailing 边缘叠加窄的、低对比渐变或 mask，颜色与单一深色 rail 融合。渐隐只能在对应方向仍有隐藏内容时出现，不能常驻遮住第一个/最后一个 item、焦点黄框、阵营底线、HP 或坐标；叠层关闭 hit testing，不得拦截水平滚动或 Button 命中。

4. **实现可见滚动提示**：在有溢出且方向可用时，显示不超过一行/一个小区域的 `chevron.left`、`chevron.right` 或同等明确的“更多/滑动”视觉提示。起点优先提示 trailing，向后滚动后提示 leading；两端均有隐藏内容时可以同时显示两侧小箭头，但不能制造高亮卡片墙。提示应随实际滚动状态更新，不依赖计时器连续闪烁；无溢出、焦点未命中或已到对应边界时不得显示错误方向。

5. **实现轻量状态提示**：可在 section 标题附近或渐隐边缘放置低对比的短状态，如“滑动查看更多”，只在该 section 真的溢出且用户需要发现滚动时显示。不得改写 `game.message`，不得新增持久规则状态；提示不应遮挡 count、section code、当前 item 或地图。若使用本地 dismiss/interaction 状态，必须在数组、尺寸、Dynamic Type 和场景切换后正确重置或重新计算。

6. **接入焦点滚动**：给 `ForEach` 的单位/据点 item 保留或明确稳定 id（单位 id、据点坐标/id），为每段建立自己的 `ScrollViewReader`。当 `game.focusedCoordinate`、`game.focusedUnit?.id` 或对应数组改变时，把匹配 item 滚到可见区域；目标消失时不滚动、不崩溃、不使用旧 id。焦点滚动只能改变该 section 的本地 offset，不能把地图焦点写回规则层，也不能因为渲染重算连续调用 `scrollTo`。

7. **处理用户滚动与 Reduce Motion**：手动横向滚动后 cue 必须准确反映起点/末端；焦点改变才允许自动定位，不要用持续 timer 或全局 drag gesture 抢夺用户滚动。读取 `accessibilityReduceMotion`：普通模式可以使用短促、低幅度的 `scrollTo` 动画或 opacity 过渡；Reduce Motion 必须无滚动动画、无闪烁/脉冲，但 cue 和完整可见性语义仍存在。

8. **守住 compact / Dynamic Type 契约**：在现有 section 高度和 item 高度预算内验证窄宽度、长单位名、据点名、`.xxxLarge` 及更大字号；短可视 code、`.large` 上限、`lineLimit`/`minimumScaleFactor` 只服务视觉，不删掉 VoiceOver 全文。不要把 edge cue 变成新的固定行，不得让 AL/OBJ/AX 任何一段挤出 rail 或压住六角地图。

9. **回归检查与文档**：完成后检查 `git diff`，确认除 `BattlefieldChrome.swift`、必要的 `BattlefieldTheme.swift` 和同步文档外无 diff；重点确认 `GameState.swift`、`GameModels.swift`、`BattlefieldMap.swift`、`BattlefieldUnitViews.swift`、`ContentView.swift`、Xcode project 和 workflow 均未被误改。同步 README、flow、flowchart、test、prompt README 和 update_log，记录本轮 cue/fade/focus-scroll 的真实行为以及 regular-only artifact 限制。

10. **提交并触发云端**：本机只做允许的 Git/文本轻量检查；在 `main` 使用 `v2.41: 增加轨道滚动提示` 提交并直接 `git push origin main`。不得创建分支、PR 或把 v2.40 旧 artifact 当作本轮结果。

## 验收标准

1. **版本与云端一致**：最新 `origin/main` 是本轮 `v2.41` commit；C 下载的 artifact manifest 中 `branch`、`commitSha`、`runId`、`runAttempt` 与远端和最新 workflow 完全一致，static、RulesSmokeTest、Xcode build-for-testing/typecheck、regular screenshot 均成功，PNG 至少 500 KB 且非黑屏。
