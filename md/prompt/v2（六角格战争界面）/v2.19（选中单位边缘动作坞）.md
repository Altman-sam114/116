# v2.19 选中单位边缘动作坞

## 版本号与分配依据

- 版本号：`v2.19`
- 分配依据：v2.18 已由 `origin/main` commit `a135f11cc4811a3e98758ac061a9f2e1cf9a8e2d`、GitHub Actions run `30192470702`、attempt `1` 和 artifact `ww2tactics-ci-v2.18-main-a135f11-run30192470702-attempt1` 完成云端验收。单位行动轨道已脱离相邻地形遮挡，下一项首屏差距是选中单位时右上动作 HUD 仍是较高的三段卡片。

## 背景

2026-07-26 核对 EasyTech《Glory of Generals 3》Google Play 官方截图：单位阵营、HP 和状态紧贴棋子，可执行命令集中在地图边缘，不用大卡覆盖战场。v2.18 云端全图中，`MapActionHUD` 仍以“单位摘要 / 四项指标 / 四个命令”三行堆叠，右上覆盖约两排六角格，与已收敛的空闲 `NEXT` 指挥坞不一致。

## 目标

1. 将选中单位 HUD 收敛为贴右上边缘的两行动作坞：上行是单位摘要、MOVE/ATK/THR/SUP 指标和待命，下行是 NEXT/ATK/POS/OBJ。
2. 四项指标改为紧凑的“图标 + 数值”，可视容器不重复 MOVE/ATK/THR/SUP 长标签，但 VoiceOver 必须保留完整标签和数值。
3. 待命按钮和四个快捷命令保持至少 44pt 点按区、既有启用/禁用条件、VoiceOver 标签和 `GameState` action。
4. 保留单位军械徽章、名称、兵种和 HP，长名使用单行压缩，不能播开动作坞。
5. 仅在 `focusedCommandPreview?.isExecutable == true` 时继续在两行动作坞下方显示现有 `InlineMapCommandPreview`；攻击前火力解算的数值和开火入口不变。
6. 在 `--ci-selected-combat-impact-steady` 截图中，右上 HUD 高度明显低于 v2.18 基线，露出更多右上战场，同时保留真实战果与 v2.18 单位轨道。

## 非目标

- 不修改 `GameState.swift`、`GameModels.swift`、行动集合、快捷命令选目标或待命规则。
- 不删除 MOVE/ATK/THR/SUP 任何数值，不删除 NEXT/ATK/POS/OBJ 或攻击前火力解算。
- 不修改地图 frame、缩放、滚动、坐标、命中、marker、单位层级或战果层级。
- 不新增动画、弹窗、第三方依赖、CI 参数、workflow 或 Xcode project 改动。
- 不触碰用户未提交的 `AGENT.md` 删除、`project.pbxproj`、`update_log.md` 与 `md/unity分析/`。

## 架构依据

- `MapCommandCenter` 已按 `selectedUnit` 在 `MapActionHUD` 和 `MapIdleCommandDock` 之间切换，本轮不改外层状态。
- `MapActionHUD` 只读 `selectedUnit`、可达/可攻击/威胁/补给集合，并转发现有 action，属于 `BattlefieldChrome.swift` 表现层。
- `MapHudMetric` 已被战役 HUD 共用；通过默认关闭的 compact 参数扩展，不改变 `MapCampaignHUD` 现有布局。
- 命令按钮保持现有 `MapQuickCommandButton` 与直接 `GameState` action，不在 View 里复制可执行判定。

## 实现步骤

1. 重排 `MapActionHUD`：第一行放缩小的 `UnitShapeBadge`、单位名/HP、4 个 compact `MapHudMetric` 和 44pt 待命图标按钮。
2. 单位摘要设定稳定但可压缩的最大宽度；regular/compact 使用不同上限，最长名称仍为单行且不遮挡指标。
3. 给 `MapHudMetric` 增加默认 `false` 的 compact 模式；compact 模式只显示图标和数值，使用固定小尺寸，并以 `accessibilityLabel("<label> <value>")` 保留语义。默认模式像素级不变。
4. 待命改用图标按钮与 `.buttonStyle(.plain)`，内容 frame 固定 44x44，已完成行动时继续 disabled，VoiceOver 标签为“待命”。
5. 第二行原样保留 4 个 `MapQuickCommandButton`，每个最小高度 44pt，容器宽度仍为 compact 268pt / regular 304pt。
6. 保持 `InlineMapCommandPreview` 条件和位于命令行下方的顺序。
7. 同步 README、flow、flowchart、test 和 prompt README；`update_log.md` 保持不动。

## 风险和禁止项

- 禁止为 HUD 新增可写 `@State`、缓存可达/可攻击数量或在 View 内复制规则。
- 禁止为追求更矮而将待命或快捷命令点按区缩小到 44pt 以下。
- 禁止仅用颜色表达指标语义；图标必须保留。
- 禁止删除或隐藏指标数值、快捷命令或攻击前火力解算。
- 禁止让长单位名换行、播宽容器或覆盖右侧指标/待命按钮。
- 禁止覆盖、暂存或提交用户和其他任务的未提交改动。
