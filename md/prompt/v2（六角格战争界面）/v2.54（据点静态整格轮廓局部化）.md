## 背景与当前问题

v2.53 已从普通态移除 threat、enemy control zone 和 supply line 三组重复整格边框，常态地图的红绿六角轮廓显著减少。当前 `--ci-selected-combat-impact-steady` regular PNG 中仍有多枚盟军、轴心和中立据点被蓝、红、黄粗完整六角边持续包围，主要来自 `HexTileView.borderColor` / `borderWidth` 对 `tile.isObjective` 的静态 fallback：普通态使用约 `0.9` opacity 与 `2pt`，attack-focus fallback 使用约 `0.72` opacity 与 `1.5pt`。

已归属据点还叠加独立 owner overlay：据点 fill 为 `0.10`，完整六角 owner stroke 为 `0.38` opacity、`0.8pt`。因此静态据点会同时消费“owner 归属层”和“通用状态 border”两套整格轮廓，形成蓝/红/黄粗边重复强调。地图已经具备足够的局部据点身份载体：

- v2.30 已把据点识别收为旗杆旗面和羊皮纸名称牌；
- v2.46 已建立 `ObjectiveLandmark`、`ObjectiveFlagMarker`、`AL`/`AX`/`NEU` 与 `ObjectiveNamePlate`；
- owner fill `0.10` 继续表达归属底色；
- v2.50 的 `HexEtchedBoundaryLayer` 继续承担地貌共享边、地形切换边和地图外缘的静态蚀刻结构。

本轮唯一主题是：**取消静态据点对通用状态 border 的特殊消费，并把据点 owner stroke 降回普通归属层强度，让据点身份由局部建筑、旗牌、文字和低强度 owner fill 承接；所有交互、命令、复盘和结果状态的高优先级完整六角边继续按原链生效。**

## 当前架构依据

- `HexMapView` 从 `GameState` 与 `TerrainTile` 只读取得 selected、focused、命令、route、coverage、capture、guided、countermeasure、pressure、AI、situation response 和 objective/owner 事实，再原样传给 `HexTileView`；本轮不改变任何参数或上游集合。
- `HexTileView` 的 owner overlay 是独立于通用 status border 的归属层：fill/stroke 直接读取 `tile.owner`，不参与 `borderColor` / `borderWidth` 的优先级判定。
- `borderColor` / `borderWidth` 是通用状态 stroke 的唯一 computed priority chain。静态 `tile.isObjective` 目前是 normal 与 attack-focus 的低优先级 fallback；删除后，更高优先级状态自然继续命中，普通静态据点自然落入最终 clear/0.45。
- `TerrainTexture` 只读 `tile.isObjective` 绘制 `ObjectiveLandmark`；`HexTileView` 继续绘制 `ObjectiveFlagMarker`、owner code 和 `ObjectiveNamePlate`。这些局部据点载体不依赖 objective border，全部保持无 diff。
- `HexEtchedBoundaryLayer` 位于地貌底层并只读邻接方向；它不读取 `tile.isObjective`，不得被强化或改造成据点替代边。
- tile 的完整 VoiceOver 摘要继续从 `tile.objectiveName` 等事实组合；装饰继续隐藏且不响应命中。本轮没有新的视图结构、状态或语义节点。
