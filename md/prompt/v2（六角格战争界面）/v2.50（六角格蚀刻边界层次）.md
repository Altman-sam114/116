## 背景与单一主题

v2.49 已把河流收敛为窄、连续、低饱和的走廊；当前地图仍需要更清楚的六角格阅读层级。`HexTileView` 目前同时承载底材、双层地格 seam、地貌纹理、道路/河流、据点、军械和多种战术 marker。若所有六角边都以同一强度出现，地图会像规则网格；若全部变弱，玩家又难以判断地块边界、地形切换和战术覆盖范围。

本轮唯一主题是：**把既有六角边界收敛为低对比蚀刻层，并让地块边界、同类地貌连续面和高优先级战术反馈有稳定的明度/线宽层级**。这是六角地图的静态表现整理，不是河道、道路、地貌纹理、HUD 或交互改版。

## 目标

1. 在 regular 战场截图中保留可辨认的六角格结构，但消除“每格硬描边”的棋盘噪声，让地图更接近 EasyTech 风格的印刷地图。
2. 让普通背景边界使用最弱的蚀刻线；同类地貌连续区域视觉上更连贯；地形切换/地图外缘可以有稍强但仍克制的边界提示。
3. 保持既有道路、河流、森林连续路径和 v2.49 river corridor 的连接几何与颜色层级；边界调整不得重新制造河流圆节或道路 lattice。
4. 保留 selected、focused、MOVE/ATK/POS/THR/SUP、据点、军械、HP/行动轨道、HIT/RET/战果、HUD 和 `AL / OBJ / AX` rail 的优先级与可读性。
5. 所有边界表现由既有 `TerrainTile`、q/r、已传入的邻接方向和局部 tile size 确定性派生；不增加游戏状态、动作或无障碍节点。

## 非目标

- 不修改 `GameState.swift`、`GameModels.swift`、战役/地图数据、地形规则、移动、攻击、补给、控制区、AI、目标、胜负或任何状态事实。
- 不修改 `ContentView.swift`、`BattlefieldChrome.swift`、`BattlefieldUnitViews.swift`、HUD、据点/单位数据、`AL / OBJ / AX` rail、输入转发或按钮 action。
- 不修改 v2.49 river-only corridor：`riverCorridorBank`、`riverCorridorChannel`、`riverCorridorHighlight`、`riverConnectionLayer` 的河流 path/宽度/高光逻辑冻结；不得借调整全局 seam 覆盖或加深河流补偿。
- 不修改道路网络、canonical edge、道路环路 quota、道路 connection path、道路颜色/宽度/高光或孤立道路逻辑。
- 不修改 `position(for:)`、tile frame/size/padding、`Hexagon` 的 `contentShape`、sibling `zIndex`、ScrollView/ScrollViewReader、scroll、zoom、focus 或三种输入手势。
- 不修改测试实现、Xcode project、workflow，不新增第三方依赖、网络、图片、SVG、纹理资产、动画、timer、缓存或随机源。
- 不以增加全屏 overlay、厚阴影、发光、blur 或强颜色来模拟边界层次；不新增文字、按钮、VoiceOver 焦点或颜色唯一语义。

## 架构依据与最小允许边界

- `BattlefieldMap.swift` 的 `HexMapView` 已为每枚 tile 计算表现层邻接方向，`HexTileView` 已按底材、seam、owner/range wash、`TerrainTexture`、marker、据点和单位的顺序绘制。只可在该既有表现链中整理边界，不得改变数据流或输入覆盖层。
- `BattlefieldTheme.swift` 是静态颜色/线条 token 的集中位置。本轮最多增加少量明确命名的 `mapEtched...` token，且必须只服务六角边界；不得重染全局 `TacticalSurface`、War Ledger、单位、河流或道路。
- 允许的 Swift 实现文件仅为：
  - `WW2Tactics/WW2Tactics/BattlefieldMap.swift`：`HexMapView`/`HexTileView` 的只读邻接边界派生与现有六角 seam 的纯绘制层级；必要时可增加 tile-local、不可命中的边段 Shape/helper。
  - `WW2Tactics/WW2Tactics/BattlefieldTheme.swift`：六角边界专用静态 token。
- 若需要修改 `TerrainTexture`，仅允许确认边界层级不会改变 road/river connection 的代码；v2.49 river 分支、`connectionPath`、`endpoint(for:in:)` 和 `RoadConnectionNetwork` 应保持无 diff。越过上述边界必须先停止并报告。

## 实现步骤

1. 在最新基线上核对 `MapGridBackdrop`、`HexTileView` 的现有 seam、`TerrainTexture`、owner/range wash 和 marker 层级；先列出实际 diff 位置，避免重复 v2.43 连续地貌、v2.47 白昼、v2.48 五类纹理或 v2.49 河流主题。
2. 将地块边界分成稳定的静态层级：普通六角背景蚀刻、同类地貌共享面的弱化边界、地形/地图边缘的轻微强调。若需要判定同类邻接，使用现有 tile/邻接事实在表现层只读派生，不能改写 `TerrainTile` 或规则连通性。
3. 复用或新增少量 `BattlefieldTheme` token，控制边界颜色、透明度、线宽和局部高光；优先采用暖纸张/墨线的低对比组合，避免蓝色河流或棕色道路被全局 token 覆盖。

6. 静态检查 compact、窄宽度、`.xxxLarge` Dynamic Type、多焦点、VoiceOver、Reduce Motion 和 4x 的源码约束：边界不得命中、不得产生无障碍节点、不得依赖动画或尺寸变化；这些条件没有独立 CI 截图时不得声称已视觉实测。

```text
TerrainTile + existing q/r + existing visual adjacency

```
