从公开白昼战场与战报画面提取的可执行观察：

- 地图通常是暖灰、浅土、浅橄榄和纸张色组成的可读底，不是纯白画布；道路、河流、山脊和城市靠局部色相、线性结构和少量阴影分层，而不是靠黑色全屏暗角。

## 背景与当前差距

v2.43 已将地图底层收敛为连续泥土/纸张战场，v2.44 建立了军械棋子材质，v2.45 建立了战果反馈层，v2.46 增强了据点地标。最新 regular 云端截图已经能同时展示六角地图、道路/河流、军械、据点、战果、HUD 和 `AL / OBJ / AX` rail，但 Agent C 明确记录整体偏暗。

当前明度来源分散在多个表现层：`BattlefieldTheme` 提供 `mapParchmentSoil`、`mapParchmentLight`、`mapParchmentShade`、`mapParchmentWash` 和接缝 token；`MapGridBackdrop` 还叠加右下黑色渐变；`HexTileView` 为每种 `TerrainKind` 使用 `mapGradient`，再叠加白/黑方向性面、owner wash、战术 wash 和接缝；`TerrainTexture` 另外绘制道路、河流、森林、山地、城市、雪地的局部阴影与高光。没有一套明确的白昼明度阶梯时，多个暗部相乘会让地图整体变脏、据点和道路退后，或者通过粗暴提亮使单位/marker 失去落地感。

本轮只解决表现层的白昼可读性：让地图底材和普通地貌更清楚，让道路/河流、据点、单位、marker、战果、HUD 和 rail 依照既有优先级保持分离。不得把本轮变成全局主题重做、信息架构重排或交互改造。

## 目标

1. 在最新 CI 的 `selected-combat-impact-steady` regular PNG 中，将地图从“整体偏暗”调整为有白昼感的暖纸张/野战底材：地图仍是第一工作区，连续地貌可读，且不发白、不刺眼、不像空白画布。
2. 建立可解释的明度阶梯：地图底材与普通地貌处于安静的中高明度；道路/河流和地貌结构用局部色相与有限阴影保持可追踪；据点和军械保持较深实体轮廓与接地关系；高优先级 marker、选中态、HIT/RET、战果结论、HUD 和 `AL / OBJ / AX` rail 仍高于静态底材。
3. 让 `TerrainKind` 的差异在白昼背景上仍然成立：平原、森林、城市、山地、雪地、河流、道路不被统一成同一块浅色；道路和河流不能因为提亮底材而断裂或消失。
4. 让 v2.46 据点锚点、v2.44 军械棋子和 v2.45 战果在新的底材上保持可读：据点地标/旗面/名称牌、单位轮廓/HP/行动轨道、交战轴线、HIT/RET/结论不能被底色吞没，也不能被新增全屏暗边或高光覆盖。
5. 优先通过 `BattlefieldTheme.swift` 的地图 token 和 `BattlefieldMap.swift` 的 `MapGridBackdrop`/`HexTileView`/`TerrainTexture` 现有表现层调整完成；不新增状态，不改变任何事实来源和动作链。
6. 以稳定、确定性的 steady-state 作为验收对象：同一地图、同一 tile、同一单位状态下，颜色/明度不随随机数、时间、战斗 phase 或消息变化。

- `BattlefieldTheme.swift` 是静态视觉 token 的集中位置。当前已有 `mapParchmentSoil`、`mapParchmentLight`、`mapParchmentShade`、`mapParchmentWash`、`mapTerrainSeam`、`mapTerrainSeamHighlight`、`mapForestContinuity` 和 `mapMountainContinuity`，应优先在这些地图专用 token 上建立白昼阶梯；不得顺手重排 War Ledger、通用 surface、单位材质或全局背景。

## 实现步骤

2. 建立小型明度阶梯并写在表现 token/局部注释中：底材为暖纸张中高明度；普通地貌有可辨色相和中等局部差；道路/河流有足够的结构对比；单位/据点/marker/HUD/rail 使用既有深色或高优先级色板保持前景；避免用同一 opacity 把所有层一起推亮。
3. 先从 `BattlefieldTheme` 地图 token 入手，只有确有必要才微调 `MapGridBackdrop` 的暗角/洗色和 `TerrainKind.mapGradient`。底材可以有非常弱的方向性明暗，但不得形成大面积营销式渐变、白色滤镜或新的动态光照。
4. 逐一审查平原、森林、城市、山地、雪地、河流和道路：普通地貌必须能在白昼背景上区分；森林/山地保留连续的接地阴影，河流/道路保留连续路径、高光和 shadow；雪地不能与底材完全融合，城市/据点不能退化成浅色块。
5. 在不改 `TerrainTexture` 层级的前提下调整纹理对比：局部阴影只用于结构，连接路径不应被底材吞没；必要时降低过重黑影、提高结构高光或使用暖灰/橄榄色替换纯黑，但不要把每个地貌变成同一套高光模板。
6. 检查静态与高优先级层的相对关系：普通底材 < 地貌结构 < 道路/河流/据点主体 < 单位/据点 owner 与状态轨道 < selected/action/威胁/路线 marker < HIT/RET/战果结论；实际代码的 zIndex 和数据流保持不变，只通过颜色、透明度、局部描边/阴影实现。
7. 针对最新截图场景检查 v2.46 据点、v2.44 四类军械、v2.45 交战结果和 `AL / OBJ / AX` rail：地图亮度提高后不得让深色军械融入底图、据点旗面失去 owner code、HIT/RET 降成普通文字，或 rail 与地图形成同一明度层。

## 数据/状态流

```text
Scenario / GameState.tiles
  -> TerrainTile(coordinate, terrain, objectiveName, owner)
  -> HexMapView 逐格传入 HexTileView(tile: ...)
  -> tile.terrain / tile.isObjective / tile.owner 只读事实
  -> TerrainKind.mapGradient + MapGridBackdrop + TerrainTexture
  -> 现有道路/河流/据点/单位/marker/战果/HUD/AL-OBJ-AX 表现层叠加
  -> HexTileView 原有 contentShape / accessibilityLabel / input chain
```

必须保持：

- 本轮只改变表现 token、纯绘制颜色和局部明暗关系；View 不写入 `TerrainTile`、`GameState` 或任何规则状态，不缓存 tile/单位/据点列表，不复制地形规则。
- 地图底材和地貌明度不读取 `game.message`、combat result、临时 phase、selected/focused 以外的推断来决定白昼模式；不得新增 `@State`、`@Published`、环境状态或用户设置。
- `ObjectiveJumpDock` 继续直接读取既有 objective 数组并调用 `game.focus(coordinate:)`；单位/敌军定位、地图输入和所有动作继续走既有链路。
- `MapGridBackdrop`、`TerrainTexture` 和所有新/改颜色层继续 `.allowsHitTesting(false)` 与 `.accessibilityHidden(true)`；`HexTileView` 仍只提供单一完整 accessibility 摘要。

## 视觉层级、叠层与几何要求

- 明度阶梯必须可解释：底材是白昼环境，不是前景；普通地貌靠色相与局部结构读出；道路/河流靠连续路径读出；据点/单位靠深色实体、旗面、轮廓和接地阴影读出；marker/战果/HUD/rail 依照既有高优先级读出。
- 任何新增或调整的底材层都必须在地图内容 bounds 内绘制，不能使用负无穷 offset、屏幕固定坐标或跨越地图的不可控 overlay；不得改变 `contentWidth`、`contentHeight`、tile frame/position。
- 不改变 `HexMapView` tile sibling 层级、attack axis 层级或 `CombatResolutionOverlay` 的 `zIndex(20)`；不靠提高底图 zIndex 或重排 overlay 解决对比问题。
- 不使用黑色大面积暗角、白色大面积 wash、强 blur、荧光描边、玻璃滤镜、厚卡片或全 tile 发光。允许的渐变必须是既有低频地图底材/地貌内部方向性渐变，并保持低对比与稳定。
- 道路/河流不应比普通地貌更暗到像裂缝，也不应比地貌更亮到失去边界；两者必须在普通、据点、单位和战果背景下仍连续可追踪。
- v2.46 据点的建筑/旗面/名称牌和 v2.44 单位的模型/HP/行动轨道不得因底图调整发生互相覆盖；v2.45 战果牌与交战轴必须保持原局部几何和优先级。
- 不修改 tile 的 `contentShape(Hexagon())`、padding、frame、位置、scroll/zoom、focus scroll 或 marker 几何；本轮只做颜色/opacity/局部纯表现调整。

## Dynamic Type、VoiceOver、Reduce Motion

- 不强制固定字体大小，不改 v2.46 `@ScaledMetric` 名称牌、v2.44 单位状态轨道、HUD/rail 的 Dynamic Type 排版；本轮若无文字改动，必须明确保持既有契约。
- 通过文字、SF Symbol、形状、描边、路径和结构保留状态语义，不能把 owner、敌我、选中、危险或战果仅编码为颜色；尊重 `accessibilityDifferentiateWithoutColor` 的既有双重编码。
