- 版本号：`v2.37`
- 分配依据：v2.36 功能 commit `1d1c5186b8504ddb2bdd022a2aa0566f270fc6fa` 已完成补给线覆盖降噪，随后文档校正 commit `d69e0ae2d78d9f84ad7daa73ecae11ebb8ae03c1` 成为当前 `origin/main` 最新状态。最终云端 run `31291811412`、attempt `1` 的 artifact `ww2tactics-ci-v2.36-main-d69e0ae-run31291811412-attempt1` 已由 Agent C 下载核对，artifact digest 为 `sha256:6ec6d20afeb0d92c8b165e18139d600b2c56dbb4aba162e51ca1d926f22f75c3`。
- v2.36 最终 `battlefield-screenshot.png`（`2064x2752`，约 `5,959,930` bytes）已实际查看：补给线、M10 暖金选中焦点、军械模型、v2.34 HIT/RET、交战结论、HUD 和 AL/OBJ/AX 均清晰；但地图上中部的相邻道路格仍将棕色连接带重复叠加为大面积三角/交叉线，地貌和兵模被抢过，因此递增 v2 小版本处理道路连接方向去重。

## 背景

当前 `HexMapView` 对每枚地格从 `tile.coordinate.neighbors.enumerated()` 找出同类地形，统一传入 `TerrainTexture.connectionDirections`。`TerrainTexture.connectionLayer(in:)` 对所有方向从本格中心向六角边界绘制 shadow、主道路带和 highlight；相邻 `.road` 六角会各自绘制同一无向边的两半，三路或多路相邻时还会在每格中心重复汇聚。`roadHighlight(in:)` 另外固定绘制每格一条水平虚线，进一步叠出棕色网格。

v2.32 已把道路连接带收窄，但最终 v2.36 PNG 证明单纯减小宽度不能解决方向重复。EasyTech《将军的荣耀3》式战场应把道路读成有方向的蜿蜒走廊，路口只保留必要分支；地貌纹理和实体兵棋应先于道路装饰被读到。本轮只改 `TerrainTexture` 的道路视觉投影，不改变任何地图规则。

## 目标

1. 仅对 `.road` 的连接绘制做稳定、确定性的无向边方向去重，使相邻道路不再为同一条边重复叠笔。
2. 在道路链、单个道路格、端点和三路/多路路口中保留连续可读的路径关系；去重后不能出现大片空断、突然截断或看不出道路的孤立短线。
3. 让 shadow、道路主体和 highlight 使用同一份去重后的几何路径；不得让 `roadHighlight` 通过固定水平虚线重新制造重复网格。
4. 保持道路连接低于单位、选中焦点、MOVE/ATK/POS、路线、火力风险、态势/复盘、据点和战果层级；道路不得遮住 M10、敌军模型、HP/行动轨道、v2.34 HIT/RET 或 v2.36 补给通道。
5. 河流和弱林带的既有邻接连续性保持；本轮不将 road 的去重规则泛化到其他地形。
6. 所有道路视觉变体仍由 `TerrainTile`、`TerrainKind`、`HexCoordinate.q/r` 与现有邻接数组只读确定性派生，不新增规则状态或随机值。

## 非目标

- 不修改 `GameState`、`GameModels`、`TerrainTile`、`TerrainKind` 的地图数据、移动力/路线成本、控制区、攻击范围、AI 或战役配置；不修改道路是否可通行的规则。
- 不修改 `HexCoordinate.neighbors` 的方向顺序、地图坐标、tile frame、`contentShape`、`Hexagon` 命中路径、`HexInputReader`、`position(for:)`、缩放、滚动范围或 tile/单位/marker `zIndex`。
- 不修改河流、水塘、森林连接、平原农田、城市、山地、雪地纹理，除非为调用接口保持兼容所需的最小纯表现改动。
- 不修改 v2.36 补给线低对比连续笔触、`GameState.supplyLineTiles(for:)`、`SupplyState`、`SUP`/`CUT`、VoiceOver；不修改 v2.35 暖金/象牙 selectedPiece、抬升、阴影或四角准框。
- 不修改 v2.34 HIT/RET 单行铭牌、交战轴线、phase、Reduce Motion、steady-state 启动桥接、动作 HUD、AL/OBJ/AX 或任何命令输入。
- 不新增图片、第三方库、网络依赖、动画/计时状态、持久化字段、View 内规则计算、复杂资产管线、workflow、CI 截图参数或 Xcode project 改动。

## 当前架构依据

- `HexCoordinate.neighbors` 的六个方向顺序是 `0=q+1,r`、`1=q+1,r-1`、`2=q,r-1`、`3=q-1,r`、`4=q-1,r+1`、`5=q,r+1`。道路去重应依据坐标和方向形成唯一无向边，不能依赖 `game.tiles` 的数组顺序或 SwiftUI 渲染顺序；常见实现可保留一组稳定的正向方向（例如 0/1/2），但必须验证端点和连续性。
- `HexMapView` 当前同时计算 `terrainConnectionDirections`、v2.36 `supplyLineConnectionDirections` 和所有 marker 集合。道路方向过滤应只作用于传给 `TerrainTexture` 的 road 视觉参数；不得改变供给、路线、地形或 `GameState` 数据。
- `TerrainTexture.connectionLayer(in:)` 目前对同一 `connectionPath` 画道路 shadow、主体和虚线 highlight；去重后这三层必须共享同一份 path。`roadHighlight(in:)` 若保留，必须沿去重路径绘制且不得固定跨整格画水平线；也可以合并为单一低对比道路高光，但不能引入第二套路径。
- `TerrainKind.showsMapConnections`、`connectionColor`、`connectionWidth` 是纯视觉扩展；道路宽度/透明度可在必要范围内微调，但本轮优先解决重复方向，不以加粗或加深补偿连续性。
- `TerrainTexture` 已 `.clipShape(Hexagon())`、`.allowsHitTesting(false)`、`.accessibilityHidden(true)`；道路装饰不得参与输入或 VoiceOver，`HexTileView` 原有 accessibility 摘要和 marker 优先级保持。
- v2.36 的补给线仍由 `GameState.supplyLineTiles(for:)` 提供，`SupplyLineMarker` 的相邻中心到边界笔触必须在道路改动后保持低对比、连续且不被 TerrainTexture 新路径覆盖。

## 验收标准

1. 最新 v2.37 `selected-combat-impact-steady` PNG 中，道路不再呈现 v2.36 所见的大面积棕色三角、菱形或交叉线；相邻道路读作一条或数条连续、细、低对比的蜿蜒走廊，路口只显示必要分支。
2. 同一条相邻道路边不会因两侧 tile 重复绘制而明显变粗；shadow、主带、highlight 的方向一致，`roadHighlight` 不再固定水平穿过每个 road hex。单格道路、端点、三路/多路路口和地图边缘均有稳定结果。
3. 河流连接、弱林带连接、平原/城市/山地/雪地纹理的既有外观和邻接连续性无回归；道路调整不改变 TerrainKind、TerrainTile、移动力、路线成本、路线预览或 AI 行为。
4. v2.36 补给线仍是低对比中心到边界连续笔触，不能被道路新 path 盖住或抢层；v2.35 M10 暖金实体底座/抬升/阴影/四角框和 v2.34 `HIT -21 / 64 -> 43`、`RET -7 / 64 -> 57`、“交火”及交战轴线继续清晰。
5. 单位模型、HP/行动轨道、选中/聚焦、MOVE/ATK/POS/路线、态势/复盘 marker、动作 HUD、AL/OBJ/AX 和地图工具栏不被道路覆盖；所有装饰仍不拦截输入并隐藏于 VoiceOver，地图摘要继续完整。
6. tile frame、`contentShape`、`HexInputReader`、坐标、缩放、滚动、zIndex、Reduce Motion 和 `GameState` 规则状态保持；源码 diff 不涉及 `GameModels.swift`、`GameState.swift`、workflow 或 Xcode project。
