## 背景与问题

当前地图虽然已有 q/r 确定性地貌、道路 canonical 无向网络、河流/森林连接、补给细通道、暖金选中与立体单位模型，但 `MapGridBackdrop` 的规则方格/斜刻线、常驻 q/r 坐标牌、每格偏亮的白色蚀刻六边和始终显示的双轴滚动条仍共同传达“地图编辑器”而非连续战场。单格地貌内已经有田块、树簇、山脊和雪纹，却缺少安静的整张泥土/纸张底与跨格连续的低频阴影，令道路、河流、森林和山体的连通性不足以成为第一眼读取的地貌结构。

本轮应建立原创的连续战区底图语言：低频、低对比、无图片的泥土/纸张底；仅在地貌变化或真实交互时才可读的六角边界；让既有道路、河流、森林、山体通过同一已存在的邻接/connection 视觉链更像跨格地物。不得复制任何 EasyTech 截图、布局、色值、贴图或素材，也不得把地图变成不可交互的静态背景或营销页。

当前 CI 只生成 `selected-combat-impact-steady` 的 regular battlefield PNG。因此 regular PNG 是本轮地图视觉的主要证据；compact、窄宽度、`.xxxLarge` 及以上 Dynamic Type、不同焦点以及 Reduce Motion 只能由源码审查，不能被 regular 截图冒充成实测证据。

## 目标

1. 去除 `MapGridBackdrop` 中规则方格线、斜向刻线与其他编辑器式网格信号，改为低频、原创、静态的泥土/纸张战区底。允许使用现有 SwiftUI 渐变、`Path`、`Shape` 与确定性几何块；不得使用图片、随机状态、时间动画、噪声贴图或新资产。
2. 默认不再绘制地图顶/左边缘的常驻 q/r `CoordinateLabel`。坐标仍必须保留在现有 tile 的完整 VoiceOver 摘要、焦点/rail 定位和规则数据中；不得改变坐标、地图尺寸、tile id 或导航语义。
3. 把普通地格的全屏白色蚀刻边显著降权：地图静止时应首先读为连续地貌而不是蜂巢线框，但六角可读性仍由非常弱的接缝/明暗分层、地貌边缘和真实地形色差维持。选中、焦点、攻击/移动/路线/补给/态势 marker、目标、单位与 HIT/RET 的既有高优先级边界和层级不可削弱。
4. 在现有 `TerrainTexture` 与其既有 `terrainConnectionDirections` 范围内增强低频连续性：
   - 道路、河流继续使用既有 canonical 道路网络和同类邻接的中心到六角边缘 path，视觉上可做细微的阴影/高光/边缘衔接调整，但不得重新推导、筛选或改变道路边集合、环路、方向、路线成本或补给逻辑。
   - 森林可把既有方向连接转化为克制的树冠阴影/边缘色块衔接，不能用高对比直线、密集图标或新 marker 取代树簇。
   - 山体可利用既有同类邻接方向让山脚阴影或山脊延续更自然；不可修改 `TerrainKind`、地图数据、山体 seed、地形类型或移动规则。
   - 平原、雪地和城镇继续保持现有确定性纹理，但不得新增会连成全图规则格线的犁沟、网格或高频重复花纹。
5. 取消普通地图双轴 `ScrollView` 的常驻可见滚动条，避免编辑器式滚动 chrome；滚动本身、双轴范围、`ScrollViewReader`、首次/焦点/缩放自动居中、鼠标/触控输入、地图缩放与 Reduce Motion 行为必须完全保持。
6. 保持地图作为主要工作区：不得抬高 HUD/rail、添加固定信息层、增加侧栏、引入静态全屏背景、遮挡单位或扩大覆盖层。地图仍需呈现六角可读性、真实单位/据点、道路、河流、森林、山体、补给、selected、MOVE/ATK/POS、路线、威胁/态势 marker、HIT/RET 和交战结论。
7. 保持完整无障碍与输入边界：装饰层必须 `allowsHitTesting(false)` 且 `accessibilityHidden(true)`；每个 tile 继续由既有 `HexTileView.accessibilityLabel` 提供地形、坐标、单位、焦点和 marker 摘要；`contentShape(Hexagon())`、tile frame、`.id(coordinate.id)`、zIndex 和 `HexInputReader` 不能改变。

## 当前架构依据

- `HexMapView` 已从 `GameState` 只读取得 tiles、选择/焦点、补给集合、路线/攻击/态势 marker 和 `RoadConnectionNetwork(tiles:)` 的道路方向；每个 `TerrainTile` 以固定 `tileWidth/tileHeight`、`position(for:)`、`.id(tile.coordinate.id)`、`HexInputReader` 和明确 zIndex 渲染。v2.43 不能触碰这条输入/状态数据流。
- `MapGridBackdrop` 位于所有 tile 下方，现在包含规则方格和斜刻线；其正确替换路径是同尺寸、无命中、无障碍隐藏的纯背景。q/r `CoordinateLabel` 目前是 `HexMapView` 中两个 `ForEach` 的常驻视觉叠层，删除其调用不会改变任何 `HexCoordinate` 或 accessibility 摘要。
- `HexTileView` 先绘制 `Hexagon` 地形 gradient、默认蚀刻边与状态 border，再绘制 owner tint、威胁 wash、`TerrainTexture`、补给/路线/marker、单位、reticle。基础接缝只能在这个低优先级起点收敛；`borderColor`/`borderWidth` 的状态优先级、tile `contentShape` 和组合 accessibility 不能重排或改写。
- `TerrainTexture` 已以 `TerrainTile`、`connectionDirections` 和 q/r `terrainSeed` 只读生成地貌。道路只接收 `RoadConnectionNetwork` 生成的方向；河流/森林接收既有同类邻接方向。v2.43 的连续性只能在此既有视觉接口内变更，不可影响 `GameState` 或路线。山地虽然目前没有独立连接线，也已收到同类邻接方向；可仅将它用于安静的渲染延续。
- `MapCommandCenter` 拥有唯一的地图双轴 `ScrollView` 和 `ScrollViewReader`：它用 `game.focusedCoordinate` 与 map scale 调用既有 `scrollTo(..., anchor: .center)`，并根据 `accessibilityReduceMotion` 决定动画。隐藏系统 indicators 只能改变表面，不能改变其滑动、聚焦、缩放、布局或无障碍逻辑。
- `BattlefieldUnitViews` 负责单位模型与组合无障碍摘要；`BattlefieldChrome` 负责 HUD/rail；`ContentView` 负责根编排/Inspector。三者只作为回归对象，不应承接本轮地貌规则或新 UI 状态。

   - 保留 `.clipShape(Hexagon())`、`.allowsHitTesting(false)` 与 `.accessibilityHidden(true)`，也不得改变 texture 在单位/marker 之下的 z-order。

7. **仅隐藏系统滚动 chrome**：在 `MapCommandCenter` 的唯一地图 `ScrollView([.horizontal, .vertical], ...)` 将 `showsIndicators` 设为 `false`。不改滚动轴、padding、`onAppear`、任一个 `onChange`、`scrollToFocusedCoordinate`、动画、compact 判定或任何 overlay；此项是去编辑器感的必要最小范围。

## 验收标准

1. **精确云端闭环**：最终 `origin/main` SHA 与 workflow `headSha`、artifact manifest 的 `branch`、`commitSha`、`runId`、`runAttempt` 完全一致；static checks、RulesSmokeTest、Xcode build-for-testing/typecheck、regular screenshot 全成功，JUnit 无 failures/errors，PNG 非黑屏且至少 500 KB。C 已登录正确账号并实际下载查看本轮 PNG。
2. **连续地貌而非编辑器**：regular PNG 中没有 `MapGridBackdrop` 的规则方格/斜刻线、常驻 q/r 坐标牌或系统双轴滚动条；地图仍保留可读而低权重的六角边界，不出现大面积白色蜂巢框。
3. **跨格连续性**：泥土/纸张底为低频、原创、静态且不抢 marker；道路/河流继续跨六角稳定衔接，森林/山体的连续块更自然，平原/城镇/雪地不产生新网格、长对角犁沟、lattice 或高频噪音。
4. **不回归战棋操作**：tile frame/position/id、`contentShape(Hexagon())`、zIndex、`HexInputReader`、handleTap/primary/secondary action、双轴滚动、焦点居中、缩放和 Reduce Motion 逻辑保持；状态 border、单位/据点、补给、路线、marker、HIT/RET 与交战结论仍在静态地貌之上可读。
5. **无障碍与响应式边界**：背景/texture/seam 纯装饰均不可命中且从无障碍树隐藏；tile 的既有完整 VoiceOver 摘要与 q/r 坐标保留。compact、窄屏、`.xxxLarge`、多焦点和 Reduce Motion 只被源码审查，报告中明确该证据限制。
6. **范围和文档闭环**：除规定的 Map/Theme 和 Chrome `showsIndicators` 单行外无源码越界；GameState、GameModels、地图数据/规则/road network、输入、ContentView、UnitViews、project、workflow 与测试实现无 diff。README、flow、flowchart、test、prompt README、update_log 与实际实现/验收事实一致。

## 风险与禁止项

- 最大视觉风险是把默认六角边削到无法辨认、把连续地貌画成新道路/补给/路线信号，或引入规则网格的替代纹理。以“静态低频背景 < 普通地貌 < 单位/目标 < selected/交战/marker”的层级审查，优先保护真实战棋反馈。
- 不得以更改 tile 位置、scale、frame、zIndex、命中形状、ScrollView、focus scroll 或 GameState 规避视觉问题；也不得把坐标信息移出无障碍摘要。
- 不得增加 `@State`、计时器、随机数、动画循环、缓存的地图事实、独立 ViewModel 或对规则的回写。所有新视觉必须由已有 inputs 在重渲染时确定性派生。
- 不得复制 EasyTech、将军的荣耀、世界征服者或任何第三方作品的具体截图、图标、地貌贴图、UI 排版、色值、素材或字体；目标只借鉴“地图优先、低噪连续地貌”的通用体验原则。
