# v2.18 单位行动状态可读性

## 版本号与分配依据

- 版本号：`v2.18`
- 分配依据：v2.17 已由 `origin/main` commit `6a2d302ac8fd3d35094a5a034c0c2f179ca0e3b8`、GitHub Actions run `30189902855`、attempt `1` 和 artifact `ww2tactics-ci-v2.17-main-6a2d302-run30189902855-attempt1` 完成云端验收。战果反馈已能自动退场，下一项地图操作缺口是单位移动/开火资源只能通过侧栏或整枚棋子的模糊降权判断。

## 背景

2026-07-26 重新核对 EasyTech《Glory of Generals 3》Google Play 官方截图。其战场把阵营环、单位模型、耐久和行动图标直接组合在棋子周围，选中态使用地面环与高对比角框，动作入口集中在地图边缘；玩家无需打开大卡即可判断部队能否继续行动。

当前 `UnitCounter` 已有军械模型、阵营地面环、将领徽章和五段 HP 条，但 `MapUnitPiece.isSpent` 只绑定 `hasAttacked`，导致“已开火但仍可移动”的单位与“移动和攻击都结束”的单位同样整体变暗。`hasMoved` 在地图棋子上没有独立信号，行动资源不够可扫描。

### Agent C 云端退回补充

- commit `9dcc8e6` 的首版与 commit `1e5d81a` 的符号修复均因完成态勾号像竖划而退回。
- commit `275ed69`、run `30191632512`、attempt `1` 的 4x 云端裁切证明根因不是字形：`UnitCounter` 超出 86x74 tile frame 的底部轨道被后续 `ForEach(game.tiles)` sibling 的地形遮挡，圆槽只剩上沿。
- 本次退回修复不再调整字形，而是在 `HexMapView` 建立稳定的地格呈现层级，使含单位的整格高于普通地形，聚焦/选中单位再逐级提升；交战轴线和战果叠层必须继续高于所有 tile。

## 目标

1. 将地图单位下方的单一 HP 条升级为固定宽度的紧凑行动状态条：左侧移动、中央 HP、右侧开火。
2. 移动和开火图标分别只读 `BattleUnit.hasMoved`、`BattleUnit.hasAttacked`；未消耗时保留明确图标与阵营外的功能色，消耗后显示固定位置的完成符号并降权。
3. 只有移动和开火均已消耗时，才将地图军械模型与地面环视为 completed/spent 并降低不透明度；底部行动状态条必须保持可读。
4. 保持现有选中地面环、四角框、HP 五段刻度、阵营码、军衔、补给、战术状态和将领徽章。
5. 保持现有 `actionStateText` VoiceOver 摘要，视觉图标作为装饰隐藏，不产生重复朗读。
6. 继续使用 v2.17 的 `--ci-selected-combat-impact-steady` 真实操作链：该场景中的 M10 已完成移动与攻击，可同时验证 completed 棋子状态和既有战果反馈。

- 不改变地图格命中、手势、选择、焦点、命令执行和 Inspector。

- 不触碰或提交用户现有 `AGENT.md` 删除、`project.pbxproj`、`update_log.md` 与 `md/unity分析/` 改动。

## 架构依据

- `BattleUnit.hasMoved` 与 `hasAttacked` 已是 `GameState` 管理的规则事实；View 只能读取，不复制或回写。
- `UnitCounter` 是地图棋子状态组合层，`MapUnitPiece` 负责军械与阵营地面环；行动图标和 HP 应在 `UnitCounter` 的稳定底部轨道表达。
- `BattleUnit.actionStateText` 已覆盖待命、已移动、已攻击、完成和防御，继续作为组合 VoiceOver 摘要。
- 固定左右图标位置比新增文字胶囊更适合高密度六角格；图标变化与明暗变化共同表达，不能只依赖颜色。

## 实现步骤

1. 在 `UnitCounter` 内派生 `isActionComplete = unit.hasMoved && unit.hasAttacked`，并把该值传给现有 `MapUnitPiece.isSpent`。
2. 用固定尺寸 `HStack` 替换独立 HP 条：左侧移动图标、中央 `MiniHealthBar`、右侧攻击图标；保持整条宽度稳定，不因状态切换改变地图布局。
3. 移动未消耗显示方向箭头，已消耗显示完成符号；攻击未消耗显示瞄准图标，已消耗显示完成符号。两侧位置稳定，图标本身变化，不能只通过青色/橙色变灰表达。
4. 未消耗移动使用克制的青色、未消耗攻击使用克制的橙色；已消耗使用低对比中性色。所有图标隐藏于无障碍树，避免与 `UnitCounter` 摘要重复。
5. `MapUnitPiece` 与将领徽章仅在 `isActionComplete` 时降低 opacity；底部行动状态条不继承该降权，单独移动或单独攻击后仍保持军械轮廓清楚。
6. 不改变 `MiniHealthBar` 的五段刻度和 HP 阈值逻辑，不增加动画。
7. 同步 README、flow、flowchart、test 和 prompt README。`update_log.md` 含用户未提交的 Unity 分析登记，本轮保持不动并在交付中说明。
8. 退回修复在 `HexMapView` 的 tile sibling 上设置只读 `zIndex`：普通地格保持基层，含单位地格高于普通地格，聚焦单位高于普通单位，选中单位最高。交战轴线和 `CombatResolutionOverlay` 必须使用更高层级。
9. 层级只能从当前 tile 是否有单位、`isFocused` 和 `isSelected` 派生；不能新增状态，不能改变 `ForEach` 顺序、tile frame、`Hexagon` 命中路径或 `HexInputReader` action。

## 验收标准

1. 每个地图单位下方稳定显示移动图标、五段 HP 条和攻击图标，状态变化不改变棋子占位。
2. 待命单位同时显示可移动与可攻击；已移动单位只把左侧切为完成；已攻击单位只把右侧切为完成；两者均消耗时左右均完成。
3. 单独攻击不再让整枚单位误显示为完全 spent；只有 `hasMoved && hasAttacked` 才降低模型与地面环，底部状态条仍清楚可读。
4. VoiceOver 仍只朗读 `UnitCounter.accessibilitySummary` 的行动状态，不重复朗读装饰图标。
5. `GameState.swift`、`GameModels.swift`、workflow 和 Xcode project 无本轮 diff。
6. steady-state PNG 继续显示静态冲击残迹、`HIT -21 / 64 -> 43`、`RET -7 / 64 -> 57` 和“交火”，并能辨认 M10 完成态的底部行动状态条。
7. 最新 `origin/main`、run、attempt 与 artifact manifest 一致，static/smoke/build/screenshot 全部成功。
8. 提交范围不包含用户现有未提交文件。
9. 云端 4x 裁切中，M10 底部状态轨道的两个圆槽、完成勾和五段 HP 均不被相邻地形覆盖；HIT/RET 和“交火”仍显示在单位上方。

## 风险和禁止项

- 禁止把 View 图标状态缓存为新的 `@State`，或从选择/焦点猜测行动消耗。
- 禁止在 View 中改变 `hasMoved`、`hasAttacked` 或回合规则。
- 禁止用两个新的文字胶囊扩大棋子高度或遮挡相邻单位；状态条必须紧凑且尺寸稳定。
- 禁止只提高 `UnitCounter` 内部 `zIndex`；它无法突破后续 tile sibling 的堆叠上下文。
- 禁止让提升后的单位 tile 遮住 `EngagementAxisOverlay` 或 `CombatResolutionOverlay`。
- 禁止仅以颜色区分可用/已消耗；图标轮廓必须随状态改变。
- 禁止加入循环动画、闪烁或不尊重 Reduce Motion 的动效。
- 禁止覆盖、暂存或提交用户和其他任务的未提交改动。
