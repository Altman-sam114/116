## 背景与问题

EasyTech 类地图战棋的有效视觉语言是地图占主位、少量高价值信息像同一块作战账本一样安静地附着在边缘，而不是由许多互不相干的圆角小卡堆叠而成。当前代码虽已将底缘定位轨道收成一块 `MapHudBackground`，但顶栏仍把 `CommandTitle`、六个 `StatusChip`、结束回合键和地图 HUD 使用为多套圆角、描边、阴影和字号层级；回合、阵营、据点、指令点、待命等真实值也在顶栏/地图 HUD 中呈现出不统一的材质密度。

本轮建立原创、克制的 **War Ledger（战区账本）** 表现语言：深色哑光指挥台底、细暖金/冷白蚀刻边、极轻内高光、受控阴影、等距紧凑字段与明确的主/次字号。它不是对任何现有游戏 UI、配色、素材、排版或图标的复制；只能使用本项目现有原创 SwiftUI 形状、颜色和 SF Symbols。重点是减少独立卡片墙和重复视觉噪音，让六角地图、单位和交战反馈仍是第一视觉层级。

当前 CI 只生成 `selected-combat-impact-steady` 的 regular battlefield PNG。因此 regular PNG 是本轮主要视觉证据；compact、窄宽度、`.xxxLarge` 及以上 Dynamic Type、多焦点状态和 Reduce Motion 必须由源码结构审查，不能被 regular 截图冒充为实拍证据。

## 目标

1. 在 `BattlefieldTheme.swift` 定义最小、语义清晰的 War Ledger 表现 token 或可复用 surface helper，使顶栏、地图 HUD 与底缘 `AL / OBJ / AX` rail 使用同一套深色基底、细边、阴影、强调色和文本层级，而不是各自重新拼装相近但不一致的黑框。
2. 重构 `TopCommandBar`、`CommandTitle`、`StatusStrip`、`StatusChip` 和 `EndTurnButton` 的纯表现层结构：顶部应读作一条单一、薄、克制的回合账本；保留真实的回合、剩余回合、当前阵营、据点控制、可用指令点、待命单位六项，不得删值、伪造汇总或以装饰替代信息。
3. 将六个 status 从彼此独立的厚圆角小卡收敛成同一账本中的字段：允许透明字段、细分隔、固定/最小行高和受控横向滚动；必须保留图标与短值的快速扫读、完整 VoiceOver label/value，以及现有 `StatusStrip` 的完整数组式遍历语义。
4. 让 `MapHudBackground` 和 `ObjectiveJumpDock` 的单一背板与顶栏共享同族材质，但不让地图 HUD、动作坞或 rail 变成更高、更亮或更多层的卡片。应保持 `MapCampaignHUD`、`MapActionHUD`、`MapIdleCommandDock` 和底缘轨道的外壳层级安静，并让轨道 v2.41 的 edge fade 与账本底色自然衔接。
5. 统一字号与对比层级：战役标题/关键行动可作为主要锚点，字段短值为次级，但不可因“统一”而缩小到不可读、删掉数值、把所有内容都变成同一亮度，或让 warning/结束回合失去可识别的危险/行动含义。结束回合仍是唯一明确的主操作，但必须以同族账本边缘与受控强调表达，不额外制造第二块醒目卡。
6. 地图仍必须占主位。不得增加固定纵向信息行、不得抬高 `ObjectiveJumpDock` 的 66pt 预算、不得把顶栏变成第二个信息面板，也不得压缩、遮挡或重新布局六角地图。
7. 保持完整可访问性：所有可见值均有完整中文 VoiceOver 语义；纯装饰背景/描边/阴影隐藏于无障碍树；所有可执行 action 保持至少 44pt 命中区域，`EndTurnButton` 继续读作“结束回合”及现有 hint；compact、Dynamic Type 与 Reduce Motion 继续成立。

## 当前架构依据

- `BattlefieldTheme.swift` 目前包含 `commandDeck`、`commandDeckDeep`、`fieldGlass`、`brass`、`signal`、`alert`、`ink`、`mutedInk` 与 `hairline` 等跨表现层 token，`TacticalSurface` 是通用表面 modifier。v2.42 可在此文件添加少量 **War Ledger 专用语义 token/helper**，但不得无差别改变全项目的 `TacticalSurface`、Inspector 或支援甲板，从而造成本轮不可控回归。
- `TopCommandBar` 由 `CommandTitle`、`CampaignPicker`、横向 `StatusStrip`、`EndTurnButton` 构成。目前 bar 使用 `commandDeckDeep` 与单一底部 brass 线；`StatusStrip` 固定输出六个 `StatusChip`，每个 chip 独立使用 `fieldGlass`、6pt 圆角和 `hairline`。本轮的主要收敛点是将它们变成一条账本的标题、字段和主操作，不触碰数据/按钮入口。
- `CommandTitle` 只读 `game.scenario.name/year`，已有组合 VoiceOver；`EndTurnButton` 只转发 `game.endTurn()`、固定 44x44pt、复用 `game.winner != nil` 禁用状态以及现有 accessibility label/hint。这些状态与行为都不可迁移至 View 本地状态或改写。
- `MapCampaignHUD`、`MapActionHUD`、`MapIdleCommandDock` 和 `ObjectiveJumpDock` 都位于 `BattlefieldChrome.swift` 的地图外壳内；它们通过 `MapHudBackground` 获得容器外观。`ObjectiveJumpDock` 保持 66pt、单一 `AL / OBJ / AX` 外层背板；其 section 项目已无独立厚背板，v2.41 的 cue 使用 `commandDeckDeep` 渐隐并关闭 hit testing。
- 因此 v2.42 的正确数据流是：既有 `GameState` 数值/标题/状态 -> 既有 Top/HUD/rail 组件 -> 只读 War Ledger token 和私有表现 helper -> SwiftUI 绘制。任何色彩、边框、阴影、间距、字号和透明度都只能是本地渲染派生，不写回 `GameState`，不触发命令。

4. **改造标题、字段与主操作的层级**：

   - `CommandTitle` 保持 WW2、战役名、年份和组合 VoiceOver，但用账本中的排版/小标记表达层级，移除不必要的孤立胶囊感；长战役名仍单行并保持可用的语义字体与可读对比。
