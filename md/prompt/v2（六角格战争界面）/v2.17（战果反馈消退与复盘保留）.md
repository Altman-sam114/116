# v2.17 战果反馈消退与复盘保留

## 版本号与分配依据

- 版本号：`v2.17`
- 分配依据：v2.16 已由 `origin/main` commit `c9560f8d3462ac2f1af897a787f51d60c3103c0d`、GitHub Actions run `30189018349`、attempt `1` 和 artifact `ww2tactics-ci-v2.16-main-c9560f8-run30189018349-attempt1` 完成云端验收。命中冲击、HIT、RET 与结论已有清晰节奏，但地图叠层会无限停留，持续遮挡战区；本轮只解决反馈退场，不扩大规则或其他 UI 范围。

## 背景

`CombatResolutionOverlay` 当前由 `CombatResultSummary.id` 驱动 `impact -> damage -> counterDamage -> resolved`，正常总时长约 330ms。进入 `resolved` 后，HIT/RET、HP、结论和静态冲击残迹永久显示，直到下一次 `GameState` 操作清理或替换 `latestCombatResult`。这使瞬时战果变成长期地图覆盖层，影响连续读图。

`latestCombatResult` 同时服务 Inspector、态势响应和复盘，不应为了隐藏地图叠层而清空。正确边界是：规则结果继续保留，地图表现层自行进入 dismissing/hidden；新 summary 到来时重新播放。

## 目标

1. 正常模式每个新战果完成 resolved 后稳定停留约 2.2-2.8 秒，再用 180-260ms 透明度过渡退场。
2. 退场只隐藏地图 `CombatResolutionOverlay`，不清除或修改 `GameState.latestCombatResult`、Inspector 结果、态势响应、日志或 AI 时间线。
3. 新 `summary.id` 到来时取消旧任务，从 impact 重新开始，并确保旧任务不能把新战果误设为 hidden。
4. Reduce Motion 取消位移和缩放，但仍允许短 opacity 淡出；若系统设置要求完全静态，直接切到 hidden 也可，不能保留永久覆盖层。
5. CI steady-state 继续固定在同一个 resolved 画面，不执行自动退场，确保云端截图能核对真实战果与 v2.16 冲击残迹。
6. 退场后的 overlay 不响应输入、不占据可访问性焦点；底层六角格输入始终可用。

## 非目标

- 不修改 `GameState.swift`、`GameModels.swift`、伤害、反击、选择、回合、AI 或结果清理规则。
- 不给 `CombatResultSummary` 增加时间戳、动画状态或 dismiss 字段。
- 不删除 Inspector 的 `CombatResultSummaryView`，不改变历史或复盘数据。
- 不加入手动关闭按钮、toast、音效、触觉、粒子、镜头震动、地图位移或循环动画。
- 不修改单位模型、地形、HUD、marker、手势、地图缩放或 Xcode project。
- 不触碰或提交用户现有 `AGENT.md` 删除、`project.pbxproj`、`update_log.md` 与 `md/unity分析/` 改动。

## 架构依据

- `latestCombatResult` 是规则事实源，必须继续存在；地图显示生命周期只属于 `CombatResolutionOverlay` 的 `private @State`。
- `.task(id: summary.id)` 天然支持新结果取消旧任务，所有延迟必须使用可取消的 `Task.sleep(for:)` 并在阶段写入前检查取消。
- `CombatResolutionPhase` 可增加 `dismissing` 和 `hidden`；phase 只决定 opacity/可访问性，不承载规则数据。
- `--ci-selected-combat-impact-steady` 已通过真实公开操作链生成 summary，`isSteadyState` 应直接保持 resolved，不进入等待或退场。

## 实现步骤

1. 扩展 `CombatResolutionPhase`，增加 `dismissing`、`hidden`，保持既有 impact/damage/counterDamage/resolved 顺序语义。
2. `playPresentationSequence()` 在进入 resolved 后等待约 2.4 秒；确认任务未取消后进入 dismissing，再等待约 220ms 后进入 hidden。
3. steady-state 分支直接设为 resolved 并返回，不能启动退场计时。
4. Reduce Motion 仍从 resolved 展示完整结果；停留结束后只使用 opacity 退场，不进行缩放、位移或冲击环扩张。
5. 在叠层根容器按 active phase 控制 opacity。dismissing 用短 ease-out，hidden 为 0；不得用条件移除导致地图布局变化。
6. hidden 阶段增加 `.accessibilityHidden(true)`，非 hidden 阶段继续只暴露现有一条组合战果摘要。装饰子 View 继续隐藏。
7. `.allowsHitTesting(false)` 保持在整个反馈层；隐藏、退场和 steady-state 均不得改变命中。
8. 新 summary 进入 task 时必须先设置 impact（正常模式）或 resolved（steady-state），不能继承上一结果的 hidden。
9. 不增加新的 CI 参数；workflow 继续使用 `selected-combat-impact-steady`，manifest 与 500 KB 截图门禁不变。
10. 同步 README、flow、flowchart、test 和 prompt README。`update_log.md` 因含用户未提交内容保持不动，并在交付说明。

## 验收标准

1. 正常模式完整战果出现后约 2.2-2.8 秒开始淡出，并在约 260ms 内完全隐藏。
2. hidden 后 `latestCombatResult` 仍存在，Inspector 与态势响应继续读取同一结果。
3. 新战果不会继承旧 hidden；旧 task 取消后不会覆盖新 phase。
4. Reduce Motion 没有缩放、位移、旋转或震动，仅以 opacity 或直接隐藏退场。
5. steady-state 永久保持 resolved，云端截图继续显示静态冲击残迹、`HIT -21 / 64 -> 43`、`RET -7 / 64 -> 57` 和“交火”。
6. 叠层始终不拦截输入；hidden 阶段不暴露 VoiceOver 元素。
7. `GameState.swift` 与 `GameModels.swift` 无 diff，所有伤害、HP、坐标和结论仍只读 summary。
8. 最新 `origin/main`、run、attempt 与 artifact manifest 一致，static/smoke/build/screenshot 全部成功。
9. 提交范围不包含用户现有未提交文件。

## 风险和禁止项

- 禁止为了退场调用任何会清空 `latestCombatResult` 的规则入口。
- 禁止 `DispatchQueue.asyncAfter`、`Timer`、不可取消延迟或 `repeatForever`。
- 禁止让 CI steady-state 进入 hidden，或延长生产停留时间到截图等待周期。
- 禁止通过写死 M10 数值、坐标或专用假 View 维持截图。
- 禁止在 hidden 后继续占据可访问性焦点或拦截六角格输入。
- 禁止覆盖、暂存或提交用户和其他任务的未提交改动。
