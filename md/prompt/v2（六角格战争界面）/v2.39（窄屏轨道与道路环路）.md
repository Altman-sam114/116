# v2.39 窄屏轨道与道路环路

## 版本号与分配依据

- 版本号：`v2.39`。
- 分配依据：当前 `origin/main` 与本地 `main` 均为 `467c9aaa727933a3e9e4483d813f0d670b587d8d`（短 SHA `467c9aa`），v2.38 云端 workflow run `31297090421`、attempt `1` 已由 Agent C 验收通过；对应 artifact 为 `ww2tactics-ci-v2.38-main-467c9aa-run31297090421-attempt1`，digest 为 `sha256:a660d3976d265706472f21adf503a55b4ee18f2dd782b3c3efbd4765c859614e`。本轮以该 commit、manifest 和 artifact 为唯一基线，不使用 Claude 附件中 v2.33 以前的旧状态替代当前源码。
- v2.38 已把地图底缘收敛为单一背板下的 `AL / OBJ / AX` 三段，并将展开 `ForceRibbon` 改为数量/READY 摘要；遗留项明确要求继续观察窄屏、Dynamic Type 和不同地图状态下的信息轨道密度。本轮只处理该遗留项以及 v2.37 道路视觉网络在环路地图上的表现缺口。

## 背景

`ContentView` 外层用 `width >= 900/760` 区分 wide/regular，而 `MapCommandCenter` 内层又以 `mapProxy.size.width < 820/680` 区分 tight/compact；这两个断点并不等价，轨道不能因为各自重新推导而在同一窄屏上出现相反模式，也不应为修复轨道去改 Inspector 的整体响应式布局。当前 `ObjectiveJumpStrip` 在 compact 下把三段强制均分，`ObjectiveJumpSection` 的标题高为 14pt、横向列表高为 50pt，`UnitFocusButton`/`ObjectiveJumpButton` 使用固定 72pt 项宽（regular 为 84pt）和 50pt 项高。当前项目文案多为固定 `.system(size:)`，长名称在窄段或大 Dynamic Type 下可能缩小到难读、被固定高度裁切，或让三段标题与项目边界不清；不能通过删除数组或缩小地图来掩盖。

`HexMapView` 的 `RoadConnectionNetwork` 当前按坐标稳定排序、只枚举方向 `0/1/2`，再以 `RoadDisjointSet.join` 保留生成树边；这解决了 v2.36 的重复 lattice，却会在含环路的道路组件中丢掉所有回边，导致阿登/诺曼底等不同地图状态下的环路读成断开的树。`TerrainTexture.connectionPath` 仍只负责把既有方向投影为中心到边界的道路笔触，不能把视觉网络改成规则路径。

## 目标

1. 让 `AL / OBJ / AX` 在 regular、compact 和大 Dynamic Type 下都保持清晰的短码、数量、分段边界和至少一个可识别项目；三段仍各自横向滚动，完整事实数组和既有顺序不变。
2. 在 `ObjectiveJumpStrip`/section/item 表现层建立明确的窄屏和大字号模式：可在大字号时收短可视名称、以图标/短码/HP/M-A 或坐标承载扫描信息，但完整名称、阵营、状态、将领、补给和动作继续由 VoiceOver 读出。视觉文字必须留在父容器内，不得遮挡标题、地图或其他轨道。
3. 保持每个轨道项目至少 44pt 的实际 Button 命中区、稳定的横向滚动和焦点边框/阵营色线；不得用 viewport 比例缩放字号、`prefix`、分页、缓存或只显示首项来伪造紧凑。
4. 将道路连接从“只剩生成树”调整为确定性的 canonical 无向边集合与密度策略：每条相邻道路边最多绘制一次；保留端点、桥接/主干和至少一个真实回边，使存在环路的组件仍读作环路；高密度路口可按坐标/方向稳定筛减次要回边或降低层级，但不能重新产生 v2.36 的重复三角 lattice。
5. 保留道路孤立格的确定性短中心笔触、河流/弱林带连接、v2.36 补给线、v2.35 selected、v2.34 HIT/RET 和所有地图输入/zIndex；道路变化只影响 SwiftUI 视觉生成，不影响移动力、路线成本、GameState 或命令预览。

## 非目标

- 不修改 `GameState.swift`、`GameModels.swift` 的规则、地图数据、`TerrainKind`、移动成本、路线算法、战役排序、单位状态或任何 `select`/`focus`/命令 action。
- 不修改 `HexTileView` 的 tile frame、坐标、`contentShape`、`HexInputReader`、ScrollView/ScrollViewReader、焦点自动滚动、marker 层级、单位模型、补给/战果/态势叠层或 `MapCommandCenter` 的地图工作区高度计算。
- 不回退 v2.37 为解决 `ForEach(game.tiles)` 类型推断而加入的显式 value collection/单一派生数组；道路改动不得把 `ForEach` 改回 Binding overload 或制造新的 ViewBuilder 类型推断回归。
- 不删除或重排 `mapFriendlyFocusUnits`、`objectiveTiles.sorted(by: objectiveSort)`、`mapEnemyFocusUnits`；不移除 `AL / OBJ / AX`、独立横向 ScrollView、ForceRibbon 摘要、TacticalOrderStrip、ReinforcementDock 或 MapLegendView。
- 不用颜色作为唯一阵营/焦点信号，不牺牲 VoiceOver、Dynamic Type、Reduce Motion 或 44pt 命中区；不把可访问性大字号实现为永久高面板或地图缩小。
- 不引入新的规则状态、网络/图片资产、第三方库、工作流参数、设备截图脚本或 Xcode project 改动；不以 Claude 附件、旧 artifact 或本地截图作为 v2.39 证据。

## 当前架构依据

- `WW2Tactics/WW2Tactics/BattlefieldChrome.swift`：`MapCommandCenter` 只读 `mapProxy` 推导 tight/compact；`ObjectiveJumpDock` 是地图 ZStack 底缘 overlay，固定 66pt；`ObjectiveJumpStrip` 的三组来源和 `objectiveSort` 是事实边界；`ObjectiveJumpSection`、`UnitFocusButton`、`ObjectiveJumpButton` 负责短码、模型、HP、M/A、旗标、坐标、焦点和 VoiceOver。若需要统一轨道模式，应在该表现层建立单一明确的语义，不得改动 `ContentView` Inspector 的 900/760 断点。
- `UnitFocusButton.focusUnit()` 必须继续让友军调用 `game.select(unitID:)`、敌军调用 `game.focus(unitID:)`；`ObjectiveJumpButton.focusObjective()` 必须继续调用 `game.focus(coordinate:)`，点选不执行命令、不消耗行动。
- `WW2Tactics/WW2Tactics/BattlefieldMap.swift`：`RoadConnectionNetwork` 由 `game.tiles` 的 `.road` 坐标只读构造；`TerrainTexture.connectionPath` 只读 `connectionDirections`，shadow、主体和 dashed highlight 共用同一 Path。网络可以重构为可测试的纯表现 helper，但不得读取或复制 `GameState` 路线规则。
- `WW2Tactics/WW2Tactics/BattlefieldTheme.swift` 的 `commandDeckDeep`、`fieldGlass`、`brass`、`hairline`、阵营色和 selected token 优先复用；不新增另一套地图色板。
- v2.38 的 `ForceRibbon` 已由 `ForceRosterSummary` 提供盟军/轴心数量和 READY 摘要，完整单位定位只在底部 AL/AX 轨道发生；本轮不得把重复单位卡加回来。
